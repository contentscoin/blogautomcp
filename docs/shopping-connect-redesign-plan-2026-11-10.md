# blogautomcp 쇼핑커넥트 재설계 계획 (v1.3.103 기준, 구현: Opus)

## Context
- 목표: 브랜드커넥트 목록을 잘 가져오고 → 링크 기준으로 썸네일·상품이미지를 배치/생성하고 → **팔리는 글**을 써서 네이버 블로그에 자동 발행. PC 연결 프로그램 + 웹 + GPT 플러그인으로 간단히.
- 현상: 여행커넥트는 동작, **쇼핑커넥트가 계속 실패**. 여러 번 고쳤지만 개선 안 됨.
- 점검 대상: main `43e84e3` (v1.3.103). 로컬 실행·실제 네이버 페이지 접속은 못 했고 코드 정독 기반 진단임.

## 진단: 왜 쇼핑만 안 되는가 (근본 원인 4개)

**R1. 쇼핑은 "근거 수집"이 약한데 글·검수는 "풍부한 근거"를 요구한다.**
- 여행은 상품 페이지의 구조화 JSON(`__NEXT_DATA__`)에서 일정·방문지를 읽는다(`scripts/simple-agent.ts:4297`, `scripts/lib/travel-content.ts:354`).
- 쇼핑은 JSON-LD + 오래된 해시 클래스 셀렉터(`._3oDjSvLwEZ`, `._1s2eOHMQjt`, `._1LY7DqCnwR` — `simple-agent.ts:4323-4440`)와 상세이미지 Codex 판독(`:748`)에 의존. 스마트스토어 상세는 대부분 이미지라 텍스트 근거가 비고, 판독이 실패하면 `SOURCE_EVIDENCE_REQUIRED`로 중단(`:4661`, `:10383`).
- 그런데 쇼핑 문체 가이드는 "작동 원리·설치·세척·보관·구조상 한계"까지 쓰라고 요구(`scripts/lib/blog-writing-style.ts:83-97`). 근거가 없으니 모델은 일반론을 쓰고, 검수는 그걸 "일반론/근거 밀도 부족"으로 막는다.

**R2. 검수가 '잘못된 글 차단'이 아니라 '좋은 글 채점'을 한다.**
- `scripts/lib/brandlink-content-readiness.ts`: 6개 카테고리 점수(통과 62점) + 필수 카테고리 + 정규식 기반 "근거→판단 연결 수", 역할 커버리지(정체·장점·한계·추천대상·결론) 미달 시 `verdict: "quality"`로 발행 불가(`:1005-1085`). 한국어 정규식 채점이라 멀쩡한 글도 떨어진다.
- 그 위에 구성 계약 게이트, 승인, 발행 전 재검사, 발행 후 감사가 겹친다. 검증 스크립트 136개, QA 문서 43개, 릴리스 노트 32개가 "막힘 → 복구/재작성 기능 추가"의 반복(1.3.98 실패 소재 재작성, 1.3.99 보완 필요 소재 보완).

**R3. 이미지 정책이 통과하기 어렵다.**
- 본문 = 원본 1 + AI 연출 3 고정(`src/lib/shopping-post-strategy.ts:11`). 연출 컷은 원본 대조 11항목 **전부 통과**, 참조 해시 일치, 발행 전 픽셀 재검사, 변경 시 승인 해제(`docs/image-generation-workflow.md`). 생성 이미지는 라벨·형태가 조금씩 틀어지므로 `IMAGE_SHORTFALL`/`REFERENCE_SCENE_FIDELITY_FAILED`가 구조적으로 잦다.

**R4. 목록 수집과 사용자 여정이 복잡하다.**
- 목록: 카테고리별 상위 100개 × 최대 36개 카테고리만 훑고(`scripts/brandconnect-seasonal-register.ts:43-54, 765-836`) 페이지네이션·검색 API가 없다. `brandKeyword`는 이 풀 안에서만 걸러서 **원하는 브랜드가 0건**이 되기 쉽다. 목록 응답의 이미지·상품 URL·카테고리도 버린다(`:438-520`).
- MCP 도구 37개, 서버 지침 12문단. ChatGPT가 동기화→준비→폴링→작성→제출→수정→이미지 3장 생성·해시 적용→승인→발행을 스스로 이어가야 한다(`apps/sites/app/api/mcp/[credential]/route.ts:29-41`).

**부가**: 프롬프트가 사용자 요구와 반대다 — "제목·소제목 이모지 금지"(`blog-writing-style.ts:43`), "구매 유도 문장은 한 번만"(`:62`). 가독성·판매 설득 요구와 충돌.

## 전략 재검토 (Threads 글 반영)
- 읽은 범위: 본문 훅만 확인됨(쿠팡파트너스 링크 삭제 이슈, 블로그에 직접 링크 없이 상위 1%가 수익 내는 우회 로직 예고). 첨부 이미지의 실제 방법론은 읽지 못함 → **사용자가 이미지 내용을 주면 반영**.
- 시사점: 네이버는 "외부 제휴 링크 + 광고성 문서"를 누른다. 쇼핑커넥트는 네이버 자체 컴포넌트라 링크 자체는 안전하지만, **글이 광고 문서처럼 보이면 같은 위험**.
- 채택 방향:
  1. 글의 주인공을 "상품"이 아니라 **검색자의 질문**으로: 고민 해결형·비교형·사용 장면형 정보글 안에 상품이 답으로 등장.
  2. 한 상품 = 전체 리뷰 1 + 각도 글 N(이미 `postAngle` 구조 있음)을 기본 동선으로 승격.
  3. 링크 카드는 답을 준 뒤(중반 1회 + 끝 1회), 고지는 상단 유지.
  4. 네이버 알고리즘 외 유입: 발행 후 Threads/SNS용 요약 문구를 함께 생성해 반환(자동 게시는 범위 밖).

## 목표 아키텍처

```
[웹 대시보드 / GPT 플러그인]  ──MCP(5개 도구)──▶ [Sites 큐] ──▶ [PC 앱]
PC 앱 파이프라인:  ① 목록동기화 → ② 상품카드(근거+이미지) → ③ 글 작성 → ④ 이미지 배치 → ⑤ 안전검사 → ⑥ 발행
```

### 사용자 여정 (목표)
1. PC 앱 설치 → 사이트에서 "PC 앱 연결" → 네이버 로그인 (현행 유지)
2. "쇼핑커넥트에서 ○○ 브랜드 5개 가져와" → 목록 카드(이미지·가격·할인) 표시
3. "1,3번 글 써줘" → PC가 근거 수집·작성·이미지·검사까지 한 번에 → 미리보기 반환
4. "발행/예약해" → 완료 URL + SNS 요약 문구

### 플러그인/웹 단순화
- 기본 노출 도구 5개: `connect_status`, `products_find`(동기화+검색 통합), `posts_write`(=materials_prepare, 한 번에 완성), `posts_preview`, `posts_publish`. 나머지 32개는 `advanced` 플래그 뒤로(호환 유지). 서버 지침은 5줄로.
- `posts_write`는 PC의 Codex로 끝까지 작성(ChatGPT가 원고 JSON을 직접 쓰는 경로는 고급 옵션).
- 웹 대시보드: 목록 → 선택 → "글 쓰기" → 미리보기 → 발행 4화면. 실패 시 "무엇이 막혔고 버튼 하나로 무엇을 하면 되는지" 한 줄.

## 구현 순서 (Opus 작업 단위, 각 단계 독립 PR)
1. **P0 계측**: 쇼핑 실패를 단계·코드별로 집계하는 리포트 스크립트(`.runtime`/작업 기록 읽기 전용) + 실제 상품 5~10개 페이지 스냅샷을 `scripts/fixtures/shopping-pages/`에 저장(사용자 PC에서 1회 캡처 필요). 이후 변경의 전/후 통과율 기준.
2. **P1 검사 완화**(효과 가장 큼, 위험 낮음): R2 hard/soft 분리, 쇼핑 전용 플래그 `SHOPPING_GATE_PROFILE=essential`. 기존 verify 스크립트 중 soft로 내려간 항목 기대값 갱신.
3. **P2 상품카드**: R1 구조화 수집 + 근거 등급 + 중단 대신 글 유형 전환.
4. **P3 이미지 v3**: 실사진 우선, AI 연출 선택화, 부족 시 감량 진행.
5. **P4 글 계약**: 프롬프트 축소·이모지/소제목/CTA 규칙·SEO/GEO 블록, 각도 글 기본 동선.
6. **P5 목록**: 필드 보존, 검색/페이지네이션, 0건 사유.
7. **P6 플러그인·웹 UX**: 도구 5개 + 대시보드 4화면, 문서(README/도구 설명) 정리.
8. 잔여 버그: MCP 설명의 OpenAI 키 문구 2곳, MCP 제출 경로의 형제 글 중복 검사 생략(`simple-agent.ts:5752`), 파괴적 루트 스크립트 삭제.

## 검증
- 단위: `npx tsc --noEmit`, CI 린트 목록, 변경 영역 `npm run test:*`(brand-post-quality, post-composition, writing-harness, shopping-natural-photos, draft-reliability, material-regression), Sites `node --test tests/*.test.cjs`.

- 실환경(사용자 PC 필요): 쇼핑 상품 10개 `posts_write` → 준비 완료율, 평균 소요, 이미지 수, 발행 1건 확인. 목표 준비 완료율 ≥ 80%.
