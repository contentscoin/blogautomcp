# 1.3.152

사진 검수 중 SDK가 보내는 `Reconnecting... 2/5 (high demand...)`는 현재 요청의 연결 복구 진행 알림입니다. 이 알림을 최종 실패로 처리해 진행 중인 검수 응답을 중단하던 경로를 보강합니다. 허용된 진행 알림은 기존 요청과 같은 이벤트 스트림에서 완료를 기다립니다. 새 검수 요청을 만들어 긍정 판정을 다시 받는 방식은 사용하지 않습니다. 사용량·인증·모델·잘못된 스키마·시간 초과와 확정된 부정 판정은 이 연결 복구 경로로 바꾸지 않습니다.

식별 글자 관찰의 허용 문자와 공백 규칙을 응답 스키마에도 적용합니다. 실제 응답에서 글자 사이에 삽입된 U+FEFF가 형식 검사 실패를 일으킨 사례를 막기 위한 변경입니다. 원시 응답을 잘라내거나 보이지 않는 문자를 제거해 통과시키지 않습니다. 실제 보이는 글자만 반환하도록 생성 시점의 규격을 강화하고 기존 문자 검증·OCR·제품 비교 기준은 유지합니다.

한 사진에서 판독 대상을 하나로 특정하지 못한 결과는 인쇄 오타나 누락이 확인된 결과와 구분합니다. 최종 원고의 상품 외형·선택 구성·사진 설명·형식 검사를 모두 통과했고 정확한 인쇄를 증명한다는 문장이 없는 경우에만, 기존의 별도 원본 비교로 해당 인쇄 위치를 비교할 수 있는지 확인합니다. 유효한 관찰 한계는 ‘인쇄 미검증’ 경고로 남기고 정상 사진을 보존합니다. 실제로 읽힌 오타, 같은 면의 노출된 인쇄 누락, 다른 옵션, 잘못된 응답과 변경된 근거는 계속 차단합니다. 이 경고는 인쇄 정확성 인증이나 새 이미지 생성 권한이 아닙니다.

옵션 충돌 판정과 그 근거는 하나의 응답 묶음으로 생성합니다. ‘충돌 없음 + 정확히 빈 근거’ 또는 ‘충돌 있음 + 서로 다른 대안 두 개 이상과 실제 전체 인용’ 중 하나를 선택해야 합니다. 충돌 여부와 근거를 따로 작성해 `true`와 빈 근거가 함께 나오던 응답 형식의 모순을 생성 시점에 차단합니다. 새 원시 응답은 그대로 저장하고 기존 검사 행으로 값을 옮길 뿐 판정을 수정하지 않습니다. 실제 옵션 충돌과 부정 판정은 계속 보존·차단하며, 과거 형식의 응답을 새 검사 결과로 재사용하지 않습니다. 외형 비교 질문도 같은 종류의 옷 두 벌을 특징 두 개로 세지 않고 목선과 소매처럼 서로 다른 실제 특징을 비교하도록 명료화합니다.

이전 원고와 정상 사진, 실패 당시의 원시 응답·전송 오류는 보존합니다. 배포 전에는 변경된 응답 규격을 실제 엔진에서 확인하고, 설치 후에는 부족한 단계만 보완해 현재 원고·사진·상품 근거의 최종 승인 상태를 다시 검산합니다. 소재 준비와 발행은 별개이며 이 복구 작업은 발행·예약을 실행하지 않습니다.
