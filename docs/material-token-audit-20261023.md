# 소재 검수 오류와 토큰 사용 점검 (2026-10-23)

## 확인된 운영 상태

PC는 MCP 조회 시 1.3.152, 온라인·유휴 상태였다. 기존 153 수정본은 Unicode 속성 정규식에 대한 실제 API 거절로 배포되지 않았다. 따라서 10월 21일의 1/4 완료 기록은 해결 완료 기록이 아니다.

## 측정

로컬 Codex 세션 중 작업 디렉터리가 `blogautomcp-codex-drafts`인 세션을 조사했다. 각 세션의 마지막 누적 사용량을 한 번만 합산했다. 캐시 입력은 입력 토큰에 포함되므로 별도로 더하지 않았다.

| 범위 | 세션 | 사용량 기록 있음 | 입력 | 캐시 입력(입력에 포함) | 출력 | 총합 |
|---|---:|---:|---:|---:|---:|---:|
| 2026-10-21 앱 전체 | 1,007 | 991 | 30,451,770 | 10,453,248 | 261,616 | 30,713,386 |
| 해당 4개 작업 시간대(UTC 04:23:52–04:50:20) | 105 | 99 | 2,511,367 | 687,104 | 18,762 | 2,530,129 |

시간대 집계는 작업별 과금 원장이 아니다. 같은 시간대의 다른 앱 호출이 있다면 포함될 수 있다. 사용량이 없는 실패 세션은 합계에 포함되지 않으며, 달러 비용·계정 한도 차감량으로 환산할 수 없다. 이 개발 대화와 검토 에이전트의 토큰도 위 앱 집계에 포함되지 않는다.

## 원인과 조치

- 사진별 외형·본문 주장·형식·인쇄를 각각 모델에 물어 한 소재에도 여러 세션이 발생한다. 이미지와 상품 근거가 각 요청에 반복 입력된다.
- 버전별 전체 정책 변경 후 같은 소재를 반복 검사했고, 긴 개발 대화를 여러 검토 에이전트에 전달한 개발 방식도 별도 소모를 키웠다.
- 배열 enum과 Unicode 정규식은 로컬 JavaScript 검사와 실제 API의 호환성이 달랐다. 모델 호출 전에 두 가지 알려진 비호환 구문을 차단하도록 추가했다.
- 출력 한도 알림을 연결 복구로 기다리면 SDK 내부 시도가 반복될 수 있었다. 해당 처리를 철회하고 첫 알림에서 중단한다. 모델·추론 설정·토큰 예산은 변경하지 않는다.
- 글자 응답의 원격 스키마에서 정규식 제약을 제거했다. 원시 응답의 Unicode·문자군·좌표·BOM 검사는 로컬 파서에서 유지한다. 단순화한 실제 요청 1회가 정상 완료됐으며, 이전 실패 응답은 보존했다.

## 아직 적용하지 않은 추가 절감안

정확히 동일한 요청·사진·역할의 서명된 검수 결과를 작업 재시작 후에도 재사용하고, 변경된 단계만 다시 검사하는 저장 캐시를 별도로 검증해야 한다. 기존 메모리 캐시나 전체 승인 영수증과 구별해야 하며, 부정 판정을 유리한 판정으로 다시 받거나 과거 결과를 현재 승인으로 승격해서는 안 된다. 이 절감안의 구현·절감률은 아직 검증되지 않았다.

배포·설치와 현재 정책에서 4개 소재의 최종 승인은 별도의 완료 조건이다. 이 점검만으로 4/4 승인 또는 배포 완료를 주장하지 않는다. 블로그 발행·예약은 수행하지 않는다.
