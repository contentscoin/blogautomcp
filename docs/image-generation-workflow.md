# 쇼핑 글·상품 참조 이미지 생성 흐름

2026-10-07 승인 샘플을 기존 생성·검증·발행 경로에 반영했다.

## 작성 기본값

`shopping-post-strategy/v1`은 글 중심 혼합형이다. 기본은 5~8절(권장 6절), 본문 1,200~2,800자, 이미지 5장이다. 기존 명시 계약과 저장 소재는 호환 경로를 유지한다.

생활의 선택 질문 → 확인된 상품 사실·구성 → 특징을 구매 판단과 연결 → 주의점·사용 계획 → 체크리스트·상품 링크 순서로 쓴다. 판매자 설명, 증빙이 있는 체험, 미확인 사항을 구분한다. 없는 구매·사용 경험을 만들거나 검증 보고 문장을 반복하지 않는다. 신규 쇼핑 문서는 제휴 고지 1개를 본문 맨 위에 놓는다.

승인 샘플은 연출사진 3장과 사실/체크리스트 카드 2장이다. 실제 상품의 기능 근거가 필요한 파트는 검증된 판매자 원본·상세 크롭·사실 카드를 사용한다. 모든 파트를 연출사진으로 대체하지 않는다.

## 상품 참조 연출사진

| 단계 | 처리 |
|---|---|
| 원본 선택 | 선택 모델·옵션의 온전하고 가려지지 않은 정면 상품을 확인한다. 기울거나 찌그러진 사진은 제외한다. 여러 개가 보이면 사용할 상품의 위치를 명시한다. |
| 참조 전달 | 실제 원본 파일을 이미지 도구에 첨부한다. 프롬프트에 참조했다고 쓰는 것만으로는 충분하지 않다. |
| 연출 | 정면 형상, 폭/높이 비율, 밀봉부·뚜껑·받침, 라벨 계층·색상을 유지한다. 배경·조명·소품만 바꾼다. 같은 상품과 원본을 유지하며, 승인된 같은 글의 대표 장면이 있으면 추가 참조한다. |
| 대조 검수 | 원본과 결과를 동시에 비전 검사한다. 윤곽·비율·상단·뚜껑/받침 정렬·라벨·색상·표면의 7항목이 모두 통과해야 한다. 응답 누락·불확실·왜곡은 실패한다. |
| 저장 | 생성 결과와 원본 참조의 SHA-256, 상품 스냅샷, 전략 버전, 검수 항목을 저장한다. 참조 파일은 패키지 안에 복사한다. |
| 발행 전 | 저장된 검수와 현재 원본·결과·상품 근거가 일치하는지 검사하고, 최종 픽셀의 상품 정체성과 문단 맥락을 다시 확인한다. |

연출사진은 `GENERATED_SCENE` / `reference-guided-scene` / `remoteGenerated=true`로 기록한다. 상품 원본이나 픽셀 잠금 합성으로 표시하지 않는다. 생성 사진의 포장·인쇄가 원본과 픽셀 단위로 동일하다고 보장하지 않는다.

사진 바로 뒤에 “상품 원본을 참조한 AI 연출 이미지” 설명을 실제 문단으로 입력한다. 소품은 연출용이며 실촬영·실사용·기능·효과의 증거가 아님을 알린다. 설명은 상품 사실 본문과 분리된 `image.caption`이다.

## 생성 경로

- PC 자동 보강은 설정된 Codex 로그인 이미지 엔진을 사용한다. 실패한 작업의 브라우저 대체는 기존 자동화 허용 설정을 따른다. 두 경로 모두 참조 파일의 누락·변경을 검사한다.
- 수동 ChatGPT 경로는 `post_get_draft` 또는 제출 결과의 `imageSlots`를 읽는다. 쇼핑 연출 슬롯의 `referenceReady=true`를 확인하고 `referenceImages`를 순서대로 실제 첨부한다. `job_get(includeResult=true)`는 원본 바이트를 MCP 이미지 블록으로 전달하며, 큰 원고가 페이지로 분리되어도 `job.imageAttachments`의 해시·첨부 인덱스를 유지한다. `imagePrompt`로 생성한 HTTPS 결과와 같은 슬롯의 `referenceHashes`를 `post_apply_section_image`에 보낸다.
- 참조 검토나 업로드가 실패하면 프롬프트를 제공하지 않는다. 기능 근거·정보 카드 슬롯도 연출 생성 프롬프트를 제공하지 않는다. PC 소재 보강에서 원본/카드를 연결한다.
- 해시 반환은 준비된 참조와 결과를 연결하기 위한 계약이다. 외부 이미지 도구가 실제로 참조를 사용했음을 서버가 직접 증명하는 기록은 아니다. 원본 대조 검수는 별도로 필수다.
- 네이티브 참조의 합계는 원문 4MiB로 제한해 공용 완료 결과의 7MiB 한도 안에 보낸다. 전송 한도를 넘으면 참조 없는 프롬프트로 진행하지 않는다.
- 여행은 기존 에디토리얼 이미지 경로를 유지한다. 쇼핑의 참조/해시 조건을 적용하지 않는다.

별도의 썸네일 스튜디오와 `thumbnail_prepare`/`thumbnail_apply_generated`는 기존 배경 생성·원본 잠금 합성 도구다. 본문/대표 슬롯의 참조 연출사진과 생성 방식이 다르며, 실제 자산의 출처에 맞게 표시한다.

## 실패와 재시도

정면 원본이 없으면 `PRODUCT_FRONT_REFERENCE_REQUIRED`, 참조 해시가 바뀌면 `PRODUCT_REFERENCE_CHANGED`, 왜곡이 남으면 `REFERENCE_SCENE_FIDELITY_FAILED`로 중단한다. 연출 생성 실패를 카드나 원본 성공으로 숨기지 않는다. 근거 파트의 사실 카드 경로는 유지한다.

작업 식별에는 전략·상품·슬롯·연출 지시·참조 해시를 포함한다. 이미 제출된 작업은 기존 체크포인트로 복구하며, 전략 변경을 이유로 같은 요청을 중복 생성하지 않는다. 외부 결과를 같은 슬롯에 다시 보내는 유효한 재시도는 `alreadyApplied`로 응답한다.

이전 전략의 미해결 제출 기록 또는 같은 슬롯의 다른 연출 요청이 남아 있으면 새 생성 요청을 보내지 않는다. Codex 요청을 전송한 뒤 응답만 끊긴 경우에도 브라우저에서 다시 생성하지 않고 기존 작업의 결과를 복구한다. 외부 적용은 완료 기록보다 실제 소재 해시를 우선 대조하며, 성공한 교체의 이전 자산 키를 다시 보내거나 적용 응답이 유실된 경우도 복구한다.

이미지나 원고를 바꾸면 이전 승인 상태를 해제한다. 선택된 발행 작업은 품질 보강으로 새 버전이 생겼을 때 자동으로 그 버전을 채택하지 않는다. 최신 소재를 검토하고 다시 선택해야 한다. 발행 스냅샷에는 상품 원본 참조 파일도 포함한다.

## 검증 범위

이번 반영은 코드와 오프라인 회귀 검사로 확인한다. 신규 원본 비교, 누락/변경 참조, 왜곡 응답, 파일 해시, 인접 설명, 동일 결과 재시도, 승인/발행 버전 유지가 주요 검사 대상이다. 실제 모델 생성과 네이버 발행 결과는 별도 실행 증거가 필요하다. 특정 이미지 모델 버전으로 실행했다고 코드 반영만으로 주장하지 않는다.
