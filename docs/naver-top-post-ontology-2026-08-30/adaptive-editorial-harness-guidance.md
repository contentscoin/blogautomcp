# 네이버 상위노출 패턴 기반 적응형 편집 하네스

## 결론

상품마다 같은 목차를 채우는 방식은 중단한다. AI는 먼저 상품 사실과 이미지, 미확인 정보를 분석해 글의 중심 판단을 정하고, 온톨로지 팩에서 관련성이 높은 판단 렌즈만 참고해 자유롭게 글을 구성한다.

온톨로지에서 관측된 빈도와 분량은 성공 공식을 뜻하지 않는다. 현재 상위 결과에서 반복해서 관측된 **편집 사전확률**이며, 상품 고유 근거가 항상 우선한다.

## 조사 범위와 해석 한계

- 수집일: 2026-08-30 KST
- 상위노출의 운영 정의: 비개인화 서버 세션에서 네이버 블로그 탭 검색 결과 1~6위
- 검색어: 쇼핑 24개, 여행 24개
- 유효 표본: 쇼핑 132건, 여행 137건
- 검색 및 본문 접근: Insane Search 통과 결과만 사용
- 저작권 원칙: 게시물 원문 전체는 저장하지 않고 URL·순위·수집시각·짧은 검색 스니펫·짧은 소제목 표본·파생 지표만 보존
- 인과 한계: 아래 패턴은 상위 결과와 함께 나타난 상관 패턴이다. 특정 패턴이 순위를 만들었다는 인과 증거는 아니다.

근거 파일:

- 쇼핑: `shopping/source-ledger.jsonl`, `shopping/analysis.json`, `packs/shopping/`
- 여행: `travel/source-ledger.jsonl`, `travel/analysis.json`, `packs/travel/`
- 배포 가능한 로컬 팩: `packs/naver-shopping-top-post-patterns-2026-08-30.zip`, `packs/naver-travel-top-post-patterns-2026-08-30.zip`
- OpenCrab 등록 정보와 서버 QA: `opencrab-registration.json`

## 관측 결과

### 쇼핑 132건

- 본문 글자 수: P25 1,220자, 중앙값 1,843자, P75 2,398자
- 이미지 수: P25 9장, 중앙값 15장, P75 21장
- 사실·스펙 93.9%, 장점 92.4%, 문제·구매동기 88.6%, 사용 장면 87.9%
- 비교 72.7%, 제품 요약 68.2%, 한계 62.9%, 가격·가치 57.6%
- 말투는 조건부 판단 89.4%, 비교형 83.3%, 대화형 81.8%, 정보형 77.3%
- 1인칭 표현은 72.0%였지만 명시적 체험 주장은 22.7%뿐이었다. 따라서 1인칭 말투 자체를 체험 증거로 취급하면 안 된다.
- 동일한 7단계 순서가 반복된 비율은 최대 1.5%에 불과했다. 공통점은 고정 순서가 아니라 **제품 사실→사용 의미→조건부 판단**이었다.

쇼핑의 기본 판단 질문:

1. 이 제품은 정확히 무엇이고 어떤 문제를 해결하는가?
2. 판매페이지·이미지에서 실제 확인된 기능·구조·규격은 무엇인가?
3. 그 사실이 어느 사용 장면에서 어떤 이점으로 이어지는가?
4. 제품 자체의 제약 또는 추천을 보류하게 만드는 미확인 성능은 무엇인가?
5. 누구에게 맞고, 누구에게는 다른 형태가 더 나은가?
6. 가격과 구성을 함께 봤을 때 어떤 조건에서 선택할 만한가?

### 여행 137건

- 본문 글자 수: P25 1,777자, 중앙값 2,197자, P75 2,742자
- 이미지 수: P25 18장, 중앙값 29장, P75 39장
- 일정 개요 100%, 교통 97.8%, 숙박 93.4%, 장점 92.0%, 예약 조건 91.2%
- 장소 가치 89.1%, 여행 동기 88.3%, 목적지 이해 86.9%, 식사 82.5%, 이동·피로 78.8%
- 한계와 준비 정보는 각각 60.6%, 추천 적합도는 54.0%
- 말투는 조건부 판단 93.4%, 정보형 90.5%, 감각적 장면 88.3%, 비교형 85.4%
- 일차별 구성은 51.8%에 그쳤다. 모든 여행상품에 날짜별 목차를 강요하면 절반가량의 상위 글 흐름과도 맞지 않는다.
- 공통점은 관광지 백과사전식 소개가 아니라 **목적지 장면→상품 동선과 조건→여행자 적합도**의 연결이었다.

여행의 기본 판단 질문:

1. 이 상품은 어떤 여행 경험과 전체 동선을 만드는가?
2. 핵심 장소는 어디에 있고, 무엇을 보며, 코스 안에서 어떤 가치가 있는가?
3. 항공·교통·숙박·식사 중 확인된 조건과 미확인 조건은 무엇인가?
4. 이동시간·보행·날씨·자유시간이 여행 강도에 어떤 영향을 주는가?
5. 포함·불포함·선택관광·출발 조건·가격 변동에서 무엇을 확인해야 하는가?
6. 상품 고유 장점과 아쉬운 점은 무엇이며 누구에게 맞거나 맞지 않는가?

## 온톨로지 적용 규칙

팩의 개념은 원고 문장이 아니라 검색·분석용 지식이다.

- `SourcePost`: 검색어, 당시 순위, URL, 수집시각이 있는 근거 출처
- `EditorialPattern`: 사실, 사용 장면, 장점, 한계, 일정, 교통 같은 관측 패턴
- `TonePattern`: 정보형, 대화형, 조건부 판단, 감각적 장면 같은 문체 신호
- `ImagePattern`: 이미지 수, 본문과 이미지 교차 정도, 콜라주 사용 여부
- `QueryGroup`: 제품군 또는 목적지군
- `AdaptiveLever`: 해당 상품에서 선택할 수 있는 편집 렌즈
- `SafetyPolicy`: 허위 체험, 미확인 수치, 카테고리 오염, 키워드 스팸 방지 규칙

조회 결과는 다음 순서로 해석한다.

1. 현재 상품과 직접 관련된 카테고리·목적지 패턴을 우선한다.
2. 전체 빈도는 표현 방식의 참고값으로만 쓴다.
3. 상품 근거가 없는 패턴은 선택하지 않는다.
4. 서로 겹치는 렌즈는 한 흐름으로 합친다.
5. 독자 의사결정에 필요하지만 자료가 부족한 항목은 지어내지 말고 `미확인`으로 판단한다.

## 런타임 하네스

### 1. 분석 단계

원고를 쓰기 전에 내부 분석 객체를 만든다. 이 객체의 라벨과 문구는 독자에게 출력하지 않는다.

```text
category
product_identity
reader_problem
verified_facts[]
image_observations[]
unknowns[]
derived_benefits[]        # fact -> meaning 근거 연결 필수
limitations[]            # 구조상 제약과 미확인을 구분
best_for[]
not_for[]
comparison_axes[]
editorial_thesis          # 글 전체를 관통하는 한 문장 판단
selected_lenses[]         # 온톨로지 후보 중 실제 근거가 있는 것만
experience_evidence[]     # 없으면 체험형 표현 금지
```

### 2. 자유 구성 단계

- 쇼핑은 보통 5~10개, 여행은 7~12개 흐름을 참고한다. 정확한 개수나 제목은 강제하지 않는다.
- 쇼핑 중앙 참고값은 7개, 여행은 9개다. Custom GPT가 숫자를 요구할 때만 호환값으로 사용한다.
- 독자 질문 하나가 짧으면 다른 질문과 합친다.
- 근거가 풍부한 장점·여행지는 더 길게 쓰고, 정보가 빈약한 항목은 별도 문단을 만들지 않는다.
- 제품/여행 분석 결과에 따라 문제 중심, 비교 중심, 장소 중심, 일정 중심 중 가장 자연스러운 흐름을 선택한다.
- 소제목은 역할 라벨이 아니라 독자가 다음 내용을 예상할 수 있는 자연어로 새로 쓴다.

### 3. 문체 단계

- 부드러운 `~요`체를 기본으로 하되 같은 어미를 기계적으로 반복하지 않는다.
- 관측 사실과 해석을 가까이 둔다: `확인된 사실 → 실제 의미 → 적용 조건`.
- 장점만 단정하지 않고 성립 조건이나 대가를 함께 둔다.
- 짧은 모바일 문단과 이미지가 교차하도록 쓴다.
- 여행은 장소를 처음 알아보는 독자가 장면과 동선을 그릴 수 있게 설명한다.
- 직접 구매·사용·방문·탑승·숙박·식사했다는 표현은 검증된 체험 메모가 있을 때만 쓴다.

### 4. 이미지 단계

- 쇼핑: 제품 원형·색상·로고·비율을 변형하지 않는다. 원본 상세 이미지 또는 잠금 처리된 제품 컷을 우선한다.
- 여행: 실제 상품 코스에 포함된 장소와 확인 가능한 계절·공간만 선택한다.
- 이미지 개수는 표본 분포를 참고하되, 중복·무관 이미지로 수를 채우지 않는다.
- 이미지는 장식이 아니라 근거다. 바로 앞뒤 문단이 이미지에서 확인할 포인트를 설명해야 한다.

### 5. 최종 품질 게이트

다음 항목 중 하나라도 실패하면 자동발행하지 않고 재분석한다.

- 상품 카테고리가 잘못 분류되었거나 다른 카테고리 용어가 섞임
- 핵심 판단이 판매 정보·이미지·안정적인 목적지 사실과 연결되지 않음
- 제품 장단점 또는 여행상품 장단점이 없고 구매·예약 안내만 존재
- 미확인 수치·호텔 등급·운영시간·가격·체험 사실을 단정
- 같은 내용을 여러 소제목으로 반복해 최소 개수를 채움
- 하네스의 `identity`, `verdict`, `purpose`, `basis`, 역할명 등이 원고에 노출
- 연결 상품과 다른 쇼핑/여행 상품이 에디터에 삽입됨
- 필수 커넥트 고지와 실제 레퍼럴 카드 검증이 실패

## 모델에 전달할 핵심 지침

```text
당신은 고정 템플릿을 채우는 작성기가 아니라 근거 기반 편집자다.

1. 먼저 상품 정보와 이미지를 분석해 확인 사실, 미확인 정보, 장점의 성립 조건,
   구조상 제약, 적합/비적합 독자를 구분한다.
2. 온톨로지 팩의 패턴 빈도는 현재 상위 글에서 관측된 참고값일 뿐이다.
   상품 근거보다 우선하지 말고, 모든 패턴을 사용하지 않는다.
3. 분석 결과를 한 문장 편집 논지로 압축한 뒤 필요한 판단 렌즈만 선택·병합·재배열한다.
   정확한 소제목 수, 이름, 순서를 맞추지 않는다.
4. 원고에서는 내부 분석 라벨과 가이드 문구를 복사하지 말고 자연스러운 새 문장으로 쓴다.
5. 각 주요 판단은 확인 사실에서 독자 의미로 이어져야 한다. 정보가 없으면 추정하지 않는다.
6. 검증된 체험 메모가 없으면 직접 써봤거나 다녀온 것처럼 말하지 않는다.
7. 쇼핑은 제품 자체를, 여행은 목적지 정보와 상품 동선·조건을 분석한다.
8. 초안 뒤 사실성, 카테고리 일치, 허위 체험, 반복, 독자 의사결정 가치를 스스로 점검한다.
```

## 구현 연결

- 코드 프로필: `scripts/lib/adaptive-editorial-harness.ts`
- 생성 파이프라인: `scripts/simple-agent.ts`
- 유연한 렌더링·품질 범위: `src/lib/post-composition-contract.ts`
- 쇼핑 분석 렌즈: `scripts/lib/product-editorial-plan.ts`
- 여행 분석 렌즈: `scripts/lib/travel-content.ts`

온톨로지 팩은 “무엇을 참고할지”를 제공하고, 적응형 하네스는 “어떻게 판단할지”를 제공하며, 렌더링 계약은 “발행 가능한 최소 품질과 이미지 배치”만 검사한다. 세 계층을 분리해 템플릿 문장이 본문으로 유출되는 문제를 막는다.
