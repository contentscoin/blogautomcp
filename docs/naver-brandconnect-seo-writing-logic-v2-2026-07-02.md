## 1. Source Rule

글쓰기 근거는 반드시 제품별 canonical solo evidence에서 시작한다.

필수 anchor:

`ANCHOR|CRAB_MICRO_TOP3|pid=<product_id>|priority=1`

필수 evidence row:

- `P`: 제품 pid, 카테고리, 검색 쿼리, 제품명
- `R1`, `R2`, `R3`: 상위 3개 블로그 URL, 제목, 이미지 수, 본문 길이, 키워드, 구조, 문체
- `D`: 이미지 목표, 필수 소제목, 핵심 키워드

OpenCrab 답변 문장이 `FAIL`, `NOT_FOUND`, anchor omission처럼 보이더라도 evidence object에 exact anchor가 있으면 evidence object를 우선한다. legacy `ANCHOR|marker=CRAB_MICRO_TOP3` 또는 compact source는 canonical solo evidence가 없을 때만 fallback으로 쓴다.

## 2. Core Title Formula

기본 제목 공식:

`[브랜드/제품명] + [핵심 카테고리 키워드] + 후기 + [주요 구매 기준] + 구매 전 체크`

변형 공식:

1. `[제품명] 후기, [사용자/상황]으로 보기 좋은 구매 전 체크`
2. `[카테고리 키워드] 추천 전 확인할 [장점]과 [아쉬운 점]`
3. `[브랜드/모델명] 사용 후기, [구성/가격/비교] 체크 포인트`
4. `[문제 상황]이라면 [제품명] [사용 포인트] 정리`
5. `[제품명] 구매 전 체크, [핵심 기능]과 [추천 대상]`

제목 후보는 7개를 기본으로 만든다. 첫 번째 제목은 가장 직접적인 exact-match형으로 만들고, 나머지는 추천형, 비교형, 사용 후기형, 구매 전 체크형으로 분산한다.

## 3. Opening Formula

첫 문단은 제품 소개보다 구매 판단 상황을 먼저 연다.

기본 흐름:

1. 해당 카테고리의 구매 고민을 한 문장으로 제시한다.
2. 왜 제품명보다 사용 목적/상황/주의점이 중요한지 말한다.
3. `이번 글에서는 [정확한 제품명]을 기준으로...` 문장으로 제품을 고정한다.
4. 핵심 키워드를 자연스럽게 나열한다.

금지:

- 첫 문장부터 `이 제품은 최고입니다`
- 효과, 성능, 건강 개선, 완벽 제거, 무소음, 최저가 같은 보장형 단정
- evidence에 없는 수치, 스펙, 가격, 성능 임의 추가

## 4. Body Structure Formula

게시용 본문은 8개 소제목을 기본 구조로 한다.

1. `[카테고리/문제상황], 왜 구매 전 체크가 필요할까`
2. `제품명에서 먼저 볼 부분`
3. `사용 장면/사용 과정 중심으로 풀기`
4. `장점으로 정리할 만한 부분`
5. `아쉬운 점과 주의할 부분`
6. `이런 사람에게 추천`
7. `구매 전 체크리스트`
8. `마무리`

이 구조는 8개 검증 초안에서 모두 안정적으로 작동했다. 카테고리별로 3번 소제목만 바꾼다.

- 펫/건강식품: 급여, 사용 루틴, 보호자 판단
- 디지털/IT: 사용 목적, 사무/학업/작업 장면
- 뷰티/헤어/바디: 사용 전후, 조작, 관리 루틴
- 가전/청소: 설치, 조립, 조작, 사용 공간
- 패션: 착용샷, 핏, 소재, 코디
- 생활/청소: 사용 전후, 소재별 주의, 관리
- 스포츠/골프: 야외 사용 장면, 크기 비교, 보관

## 5. Paragraph Logic

본문은 소제목마다 2-4개의 짧은 문단을 쓴다.

문단 역할:

- 첫 문단: 독자의 구매 상황과 문제를 받는다.
- 둘째 문단: evidence의 제품명/카테고리/키워드를 자연스럽게 풀어준다.
- 셋째 문단: 실제 사용 장면 또는 촬영 포인트로 연결한다.
- 넷째 문단: 주의점 또는 구매 전 확인 사항으로 신뢰를 만든다.

문체:

- 기본: 체험형, 추천형, 정보형, 비교형, 친근체
- 너무 광고처럼 단정하지 않는다.
- `좋습니다`보다 `확인하면 좋습니다`, `살펴볼 만합니다`, `비교하는 편이 좋습니다`를 우선한다.
- 장점 섹션 뒤에는 반드시 아쉬운 점/주의점 섹션을 둔다.

## 6. Keyword Placement Rule

키워드는 한 문단에 몰아넣지 않는다.

배치:

- 제목: 제품명 + 카테고리 + 후기/추천 + 구매 전 체크
- 첫 본문 4문단 안: 정확한 제품명 1회, 핵심 키워드 묶음 1회
- 제품명 해체 섹션: 모델명, 카테고리, 검색 쿼리 키워드
- 장점 섹션: 넓은 카테고리 키워드로 확장
- 구매 전 체크리스트: 기능/구성/가격/주의 키워드
- 마무리: 제목 키워드를 자연스럽게 1회 반복

반복 금지:

- 같은 exact keyword를 매 문단 반복
- 제품명을 과도하게 반복
- 카테고리 키워드 없이 브랜드명만 반복

## 7. Image And Thumbnail Rule

사진 수는 `D|img=<n>`을 그대로 따른다. 증감이 필요하면 Evidence Note에 이유를 남긴다.

썸네일 공식:

`제품 실물 + 사용 맥락 + 짧은 키워드`

카테고리별 hero 컷:

- 펫/건강식품: 제품 패키지 + 반려동물/급여 맥락
- 디지털/IT: 제품 오픈 컷 + 실제 작업 공간
- 뷰티/헤어/바디: 본체/구성품 + 사용 장면
- 가전/청소: 제품 전체 + 공간 사용 장면
- 패션: 착용샷 + 제품 구성
- 생활/청소: 사용 전후 또는 사용 과정
- 스포츠/골프: 야외/골프백 맥락 + 크기감

사진 흐름:

1. 썸네일용 대표 컷
2. 패키지/구성품
3. 제품 디테일
4. 사용 준비
5. 실제 사용 장면
6. 장점 요약 컷
7. 아쉬운 점/주의점 요약 컷
8. 구매 전 체크리스트 이미지

## 8. Trust-Building Rule

상위노출형 글은 장점만 밀지 않는다. 모든 초안은 아래 균형을 유지한다.

- 장점: 제품명, 카테고리, 사용 장면, 사진 구성 포인트
- 아쉬운 점: 체형/환경/소재/사용 목적/관리 난이도/상세페이지 확인
- 추천 대상: 4-5개 bullet
- 반대 조건: 적합하지 않을 수 있는 사용자 1문단
- 구매 전 체크리스트: 7-8개 항목

## 9. Compliance Guardrail

다음 표현은 제품명 또는 경쟁글 제목에 있더라도 게시 본문에서는 단정하지 않는다.

- 건강/효능: 치료, 개선 보장, 완치, 즉시 효과
- 펫/영양제: 장건강 해결, 반드시 낫는다, 급여 효과 보장
- 청소: 완벽 제거, 새것처럼, 즉시 제거, 100%
- 가전/헤어: 완전 무소음, 무조건 조용, 건조 시간 단정, 수치 임의 추가
- 패션: 누구나 잘 맞음, 핏 보장, 최저가 보장
- 스포츠/우산: 강풍에도 절대 뒤집히지 않음, 자외선 완벽 차단, 할인율 보장
- 디지털/IT: 실제 무게, 성능, 배터리, 사양 수치 임의 추가

대체 표현:

- `상세페이지 기준으로 확인해야 합니다`
- `사용 환경에 따라 체감이 달라질 수 있습니다`
- `구매 전 체크 포인트로 보는 편이 안전합니다`
- `먼저 살펴볼 만합니다`

## 10. Output Contract

워크플로우는 항상 아래 섹션을 출력한다.

1. 제목 후보
2. 게시용 블로그 본문
3. 사진/썸네일 계획
4. 내부 SEO QC
5. Evidence Note

Evidence Note 필수 항목:

- canonical document_id
- source
- source_url
- required rows present
- top competitor image/body evidence
- extracted pattern
- image target
- fallback 또는 legacy source 사용 여부
