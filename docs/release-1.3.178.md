# 1.3.178

1.3.177 코드 점검에서 찾은 최우선 문제 두 가지를 고쳤습니다. 여행커넥트는 바뀌지 않습니다.

## 검수받지 못한 사진이 통과하던 문제
- 최종 이미지 검수 호출이 시간 초과·전송 오류로 재시도까지 실패하면 그 사진은 검수를 받지 못한 것입니다. 지금까지는 이 경우도 "판정 없음"으로 기록해서, 판매자 원본 사진과 사진 썸네일이면 권고로 내려가 검수 없이 준비완료가 될 수 있었습니다. 이제는 "검수 호출 실패"(`REVIEW_CALL_FAILED`)로 따로 기록하고 발행을 막습니다.
- 승인 단계는 같은 사진을 한 번 다시 검수합니다. 그래도 실패하면 원고와 사진을 그대로 둔 채 멈춥니다. 사진을 새로 만들거나 원고를 다시 쓰지 않으며, 검수 연결이 돌아온 뒤 소재를 다시 준비하면 됩니다.
- 검수 응답의 형식 오류("판정 없음")를 판매자 원본 사진에서 권고로 남기는 1.3.176 동작은 그대로입니다.

## 로컬 서버 보호
- 관리자 키 없이 쓰는 기본 설치에서, 다른 웹사이트가 사용자의 브라우저를 통해 PC의 앱에 발행·수정·삭제 요청을 보낼 수 있던 문제를 막았습니다. 다른 사이트에서 보낸 브라우저 요청과, IP 주소나 `localhost`가 아닌 호스트 이름으로 들어온 요청은 거부합니다(403 `LOCAL_REQUEST_REQUIRED`).
- 앱 화면, 앱이 내부에서 보내는 요청, 출처 헤더가 없는 스크립트(curl 등), IP 주소로 여는 접속은 그대로 동작합니다.
- 별칭·터널·프록시처럼 다른 호스트 이름으로 앱을 열어야 하면 `.env`의 `LOCAL_ALLOWED_HOSTS`에 이름을 쉼표로 적거나 `ADMIN_API_KEY`를 설정합니다.

## 테스트
- 실패한 채 CI 밖에 있던 `test:thumbnail-studio`, `test:mcp-activation`을 현재 동작에 맞게 고치고 `test:api-auth`와 함께 CI에 넣었습니다.

실제 PC에서의 동작은 이 버전에서 처음 확인합니다. 확인할 것: 앱 화면에서 소재 준비·발행·설정 저장이 평소처럼 되는지, 검수 연결이 끊긴 상태에서 소재가 "검수 호출 실패" 사유로 멈추고 연결이 돌아온 뒤 다시 준비하면 통과하는지.
