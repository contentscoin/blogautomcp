# 원고 작성 시간 예산

평균 약 5분인 전체 원고 작성을 위해 Codex와 브라우저 응답 1회 기본 상한을 10분으로 둔다. 브라우저의 최초 작성, 정지 후 1회 재시도, 구조 보완은 모두 같은 응답 예산을 사용한다. 이전의 120/150/180초 idle 및 300/420초 직접 작성 제한은 제거했다.

실제 응답 텍스트가 5분간 바뀌지 않으면 기존 정지 복구 절차가 실행된다. 생성중 표시, DOM 변화, 대기 로그는 이 시간을 갱신하지 않는다. 전체 10분 상한은 텍스트가 계속 바뀌어도 연장되지 않는다. 기존 QC, 재시도 횟수, fallback 조건은 유지한다.

| 환경 변수 | 기본값 | 범위 |
| --- | --- | --- |
| CODEX_DRAFT_TIMEOUT_MS | 600000 (10분) | Codex 작성 1회 |
| CHATGPT_RESPONSE_IDLE_TIMEOUT_MS | 300000 (5분) | 실제 응답 텍스트 무진행 |
| CHATGPT_RESPONSE_MAX_TIMEOUT_MS | 600000 (10분) | 브라우저 응답 1회 |
| AGENT_MAX_RUNTIME_MS | 9000000 (실효 150분) | 수집/작성/이미지/QC 포함 에이전트 전체 |
| REMOTE_DRAFT_PREPARE_WAIT_MS | 9300000 (실효 155분) | 원격 준비 호출 대기 |
| REMOTE_DRAFT_GENERATE_WAIT_MS | 9600000 (실효 160분) | 원격 생성/수정 호출 대기 |

이 값은 정상 소요시간이 아니라 최대 대기 예산이다. `simple-agent.ts`의 품질 보강은 쇼핑 최대 2회, 여행 최대 3회다. 여행 최초 작성까지 합치면 4회이고, 각 브라우저 호출은 최초 응답·정지 재시도·구조 보완을 각 10분까지 기다린다. 따라서 작성 최악 합계는 `4 × 3 × 10 = 120분`이다. 수집·브라우저 준비·이미지·저장 등을 위한 30분 여유를 더해 에이전트 최소 150분, 바깥 준비/생성 호출은 각각 추가 5분씩 둔다. 초안의 고정 90/95/100분만으로는 이 경로가 들어가지 않아 계산된 최소값이 우선한다. 선택적으로 Codex→브라우저 fallback이 켜지면 `4 × (10 + 30) + 30 = 190분`이 에이전트 최소값이 된다.

이미지 예산은 별도 image-timeout-policy에서 관리한다. 30분 여유는 모든 이미지가 장당 최악 타임아웃을 소진하는 큰 배치까지 보장하지 않는다. 그런 배치의 전체 합계는 이미지 담당 정책과 별도 조정해야 한다. 원격 준비/생성 호출보다 자식 에이전트가 먼저 종료되도록 최소값을 연결한다. heartbeat 30초와 lease 갱신 규칙은 바꾸지 않는다.

기존 환경 변수와 Codex timeoutMs 호출 옵션은 유지된다. 개별 명시 설정은 최소 1분(에이전트는 5분), 최대 3시간으로 제한하며 빈 값·0·음수·NaN·Infinity는 기본값으로 복구한다. 그 뒤 부모 설정은 계산된 자식 합계 이상으로 올린다(계산 결과는 3시간을 넘을 수 있지만 유한하다). 기존 .env 파일을 수정하지 않아도 15/20분 AGENT_MAX_RUNTIME_MS 및 30분 REMOTE_DRAFT_GENERATE_WAIT_MS는 더 이상 작성 체인을 먼저 끊지 않는다. 최소값보다 큰 명시 설정은 유지한다. CHATGPT_TIMEOUT_MS는 입력창 준비 시간이며 응답 idle의 대용이 아니다.

검증: `npx ts-node --project tsconfig.scripts.json scripts/verify-writing-timeouts.ts`. 가상 시간과 정책 연결 검사만 사용하며 실제 생성 요청은 보내지 않는다.
