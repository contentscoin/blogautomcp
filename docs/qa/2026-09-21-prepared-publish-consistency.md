# 준비 완료 후 발행 실패: 1.3.74 검증

## 확인한 원인

- 샥즈 `893dcd81-c3ca-4a0c-ac45-9ae96296c28e`: v2 승인 문서는 본문 8개인데 `##` 없는 내보내기 Markdown을 구형 파서로 읽어 1개로 집계했다. 실제 저장 파일로 재현했다.
- 삼성 `7bbf917f-77c5-418c-9145-a241fcf8f2e3`: 원본 선정과 발행 시각 검사가 별개여서 준비에서 통과한 사진이 발행에서 거절됐다. 표시된 원문 reason은 상품 정체성 설명뿐이어서 실제 실패 조건인 기능 근거 부족을 숨겼다.
- 실제 원본 교체에서도 이미 다른 파트가 사용 중인 동일 파일을 후보로 다시 선정해 중복 적용 검사에서 막혔다.
- 사양표 하단의 작은 저작권 문구를 공지 이미지로 오인했고, 함께 검사하는 다른 후보를 정품 기준처럼 사용해 판정이 흔들렸다.
- 동일한 문서·사진을 준비와 발행에서 매번 다시 모델에 판단시켜 결과가 달라질 수 있었다.

## 수정

- v2 원고는 정본 renderNodes에서 본문을 복원한다. 최소 5개 본문 기준과 승인 확인을 유지하고, 이전 형식만 Markdown 파서를 사용한다.
- 이미지 후보를 발행과 같은 선택 상품 문맥·시각 규칙으로 검증한다. 선택된 후보만 검사하며 부적합 조합을 제외한 대안 선택은 최대 3회다.
- 이미 사용 중인 대표·다른 파트 사진은 후보 단계에서 해시로 제외한다. 명시적인 교체 대상과 미배정 원본은 보존한다.
- 승인 전에 전체 최종 이미지 검사를 실행한다. 확정적인 의미/비율 실패는 원본 복구 후 한 번 재검사한다. 다시 실패하면 검증된 대안으로 실제 배치가 바뀌고 필수 수량을 모두 채운 경우에만 마지막 검사를 허용한다.
- 기능 슬롯을 일반 사진으로 대체하지 않는다. 확정적으로 거절된 대표·생활 장면만 일반 사진이 허용된 다른 파트로 이동할 수 있다. 본문, 이미지 의도, 전체 필수 수량, 생성 필수 정책을 보존한다.
- 대안 탐색 중 추가한 사진은 실제 선택된 파트만 최종 구성에 남긴다. 선택되지 않은 신규 후보는 게시 목록에서 제외하되 원본 파일과 검증 진단은 보존한다.
- 전체 최종 감사 성공만 서버 기록으로 저장한다. 이미지 전체 해시·순서·파트·선택 상품·실제 문장·실제 감사 프롬프트·모델 설정이 같을 때 재사용한다. 발행에서도 파일 전체 디코딩과 규격·해시 검사를 수행한다.
- 감사 기록은 AppData별 키로 HMAC 서명한다. 변경·강제 검사·실패·인증 오류는 이전 성공을 무효화한다. 주입한 테스트 검토자는 운영 기록을 만들지 않는다.
- 감사와 거절 기록 갱신을 같은 OS 잠금으로 묶는다. Windows 명명 파이프 소유 프로세스가 종료되면 OS가 잠금을 해제한다.
- 공개 오류에 실제 실패 조건과 해당 문단을 함께 표시한다. 작은 저작권 하단 문구만으로 제품 사양표를 공지로 거절하지 않는다.

## 실제 소재 검증

- 기존 두 시도는 제출 전 실패였으며 중복 게시 가능성이 있는 불확정 결과와 구분했다.
- 실제 샥즈 v2 로더: 본문 8개 + 고지문 1개 확인. 원고를 다시 생성하지 않았다.
- sourceOnly 복구를 사용했으며 유료 이미지 생성은 실행하지 않았다.
- 삼성 회색 후보는 선택 모델의 화이트 사양과 충돌함을 직접 확인해 제외했다. 근거: 저장된 선택 모델 사양표 및 [삼성 공식 사양](https://www.samsung.com/sec/support/model/DV21DG8600BW/).
- 샥즈는 반복 거절된 생활 장면 대신 가격 파트의 검증 원본으로 배치 변경 후 실제 전체 시각 검사 5/5 통과했다.
- 삼성의 첫 원본 교체는 다시 기능 근거 부족으로 실패했다. 재배치에서 선택하지 않은 후보까지 본문에 남는 문제도 발견해 수정했다. 현장 소재에서는 이미 추가된 선택하지 않은 선택사항 사진을 제거한 뒤, 필수 5장을 유지하는 대체 배치로 최종 검증했다. 원고와 필수 수량을 줄이지 않았다.
- 최종적으로 두 소재 모두 실제 모델 시각 감사 5/5 통과. 두 번째 동일 입력 검사에서 서명된 성공 기록 재사용도 확인했다.
