# Windows 1.3.140: 선택 갤러리 근거와 자연스러운 정물사진 검수

이 변경은 비교 자료 누락과 사진 역할 해석을 보완합니다. 문서 작성 시 설치된 1.3.139의 실제 소재 상태는 준비완료 7/10개입니다. 1.3.140의 빌드·업데이트 배포·설치·최종 소재 승인은 아직 수행하지 않았습니다. 아래 사전 검수 성공을 전체 소재 승인이나 발행 성공으로 간주하지 않습니다.

## 변경한 입력과 인코딩

기존 비교자료 선택은 갤러리 앞쪽 원본, 수량을 발견한 자료, 실제 발행 원본을 우선했습니다. 판매목록에 존재하는 상세 카탈로그가 이 선택에서 빠져, 사진이 해당 판매목록의 외형인지 판단할 근거가 부족한 사례를 확인했습니다. 기존 선택을 모두 마친 뒤 총 5장 제한에 빈자리가 있는 경우에만 정적 세로 상세 후보 1장을 추가합니다. 긴 변은 4,096px 이하이며 세로 비율과 원래 갤러리 순서로 발견합니다. 상품명·SKU·해시별 예외는 없습니다.

추가 자료는 비교 전용입니다. 세로형이라는 이유로 카탈로그, 구성품 포함 여부, 확정 구매 옵션을 승인하지 않습니다. 현재 선택 스냅샷의 URL, 원본·영수증 SHA, 정적 전체 디코딩과 재검증을 유지하며, 서로 다른 원본이 같은 URL에 연결되면 계속 제외합니다. 기존 앞쪽 원본·수량 근거·발행 원본을 추가 자료가 밀어내지 않습니다. 카탈로그 표나 판매자 홍보 문구는 본문 이미지로 사용할 수 없습니다.

사진 1장은 물리적 제품 1개라는 뜻이 아닙니다. 같은 선택 상품의 여러 개체가 참조와 상품 근거에 맞게 한 공간에 놓인 자연스러운 정물사진도 하나의 사진일 수 있습니다. 실제로 제품 1개를 요구하는 슬롯, 본문의 전체 구성·수량 단정, 다른 옵션이나 SKU, 붙여넣은 복제, 불가능한 배치·비율, 충돌하는 식별 표기와 해결되지 않은 정체성은 계속 거절합니다. 반환된 불리한 판정을 다른 유리한 필드로 바꾸지 않습니다.

추가 상세자료를 기본 PNG로 전개했을 때 기존 최종 사진·필수 참조와 합쳐 6개 후보가 전송 한도를 넘었습니다. 이 실패 측정은 보존했습니다. 해결은 해상도나 비교자료를 줄이는 대신 공통 `encodeLosslessAuditSnapshot`에서 기본 PNG와 `compressionLevel: 9`, `adaptiveFiltering: true`, `palette: false` PNG를 순차 생성하여 더 작은 결과를 사용하는 것입니다. 최종 사진·직접 연결된 참조·갤러리 snapshot에 동일하게 적용하고 기존 참조 캐시를 재사용합니다. 원본 파일은 쓰지 않으며 JPEG 분기, 리사이즈, 크롭, 팔레트 양자화, 손실 재인코딩은 추가하지 않았습니다. 두 인코딩에 따른 CPU·일시 메모리 비용은 남습니다.

## 확인한 결과

| 검증 | 결과와 범위 |
| --- | --- |
| 실제 전체 해상도 픽셀 | 공통 production encoder를 사용한 97개 고유 입력에서 기본 PNG 대비 치수·전체 raw 채널(알파 포함) 지문 동일 |
| 실제 전송 계획 | 10개 소재의 최종 이미지 50개 모두 기존 planner로 검수 가능. 최대 그룹 7,650,331바이트·6첨부로 기존 8MiB·8첨부 이내 |
| 전송 측정의 원본 보존 | 관찰한 사용자 파일 503개 전후 바이트 동일 |
| 오프라인 회귀 | selector 73건·최종 감사 189건·참조 74건, 합계 336건 및 배칭·초과 용량 차단 회귀 통과 |
| 통합 검사 | 전체 TypeScript·소재 회귀 29개 suite·소유 파일 lint 통과 |
| 실제 Codex 사전 검수 | 기존 파일을 사용한 두 소재의 최종 이미지 각 5개 모두 통과. 이어 최종 첨부 하나만 명백히 다른 상품으로 바꾼 음성 사례에서 `identityMatches=false`와 `accepted=false` 확인 |
| 사전 검수 보존 | 사용자 파일 442개와 소스 17개 전후 동일. 승인·거절기록 변경·이미지 생성·블로그 발행 없음 |

실제 사전 검수는 기존 production `auditPublishImages`와 `runCodexDraft`를 사용했습니다. 실제 호출은 양성 10회와 음성 1회, 총 11회이며 기존 모델·재시도 정책을 유지했습니다. SDK 내부 네트워크 시도 횟수는 별도로 계측하지 않았습니다. 불리하거나 형식이 잘못된 결과가 나오면 중단하는 단일 실행이며, 유리한 답을 얻기 위한 동일 검수 반복이 아닙니다. 패키지 식별자를 전달하지 않은 감사 경로로 성공 영수증·거절 registry·소재 승인 상태를 변경하지 않았습니다.

스키마 구조, boolean 파서, 불리한 필드의 차단 조건과 최종 판정 gate는 그대로입니다. 정책 파일 목록 15개 중 2개의 바이트가 의도적으로 변경되었고 나머지 13개는 설치된 1.3.139의 동결 소스와 같습니다. 공유 규칙을 참조하는 스키마 설명 문자열과 정책 지문은 변경됩니다. 성공 HMAC 영수증은 실제 요청·픽셀·정책에 묶여 있으므로 이전 영수증이나 승인 상태를 새 정책의 성공으로 재사용할 수 없습니다. 배포·설치 후 실제 네이티브 경로에서 새 최종검수와 승인이 필요합니다.

## 남은 완료 조건

1. 독립 채택 검토를 마친 소스로 빌드·패키징·정상 업데이트 설치를 검증합니다.
2. 기존 원고와 정상 사진을 유지한 채 실제 네이티브 최종검수·승인 결과를 확인합니다. 과거 거절 기록은 사전 검수 결과만으로 지우지 않습니다.
3. Offon의 과거 발행 확인 보류는 별도로 유지합니다. 이 변경으로 중복 발행 가드를 해제하거나 블로그 발행·예약을 실행하지 않습니다.

세로형 자료 발견은 의미상 가장 유용한 카탈로그를 항상 고른다는 보장이 아닙니다. 실제 사전 검수 결과도 다른 상품·옵션·본문에 대한 자동 승인 근거가 되지 않습니다. 원고·사진 원본과 과거 실패 측정은 보존하며, 현재 설치 상태와 새 버전의 검증 상태를 구분합니다.
