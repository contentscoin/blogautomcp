# Windows 1.3.135: bounded seller-photo search fairness

The unreleased 1.3.134 installer passed its package and isolated updater checks. The installed 1.3.133 material workflow continued while that package was prepared. It exposed an additional search-order problem in final seller-original recovery: a generic appearance slot may allow both product photographs and natural seller scenes, but every final-audit round preferred remaining product-photo proposals. Six unsuitable product photographs could exhaust the existing six-round budget before an eligible scene received a final verdict.

An isolated counterexample uses the actual selector and final-audit loop with synthetic pixels and explicit fake semantic verdicts. Six rejected product-photo proposals leave a seventh scene unreviewed, even when that scene is first in the input list. Rebuilding a static interleaved list on every round has the same defect. This proves search starvation under the stated fixture; it does not approve any real seller image.

The narrow follow-up retains the most recent full-audit rejection class per target within the current call. For generic appearance targets that already permit both classes, a different permitted class receives the next opportunity when available. The first choice, same-class ordering when no alternative exists, eligibility filters, distinct-source matching, the six-round budget and all final pixel, product, option, provenance and byte-change checks remain in force. A rejected pair never re-enters through ordering. Provider quota and transport failures still stop the operation.
