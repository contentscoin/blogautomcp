# Material recovery 1.3.119

The installed 1.3.118 Minix-only repair exposed two additional issues. A completed generation receipt was reused for the same slot/reference/snapshot even when the scene recipe and request identity changed. The current kitchen recipe therefore reviewed the old laundry photograph instead of generating the requested new scene. Existing Minix sidecars contained no scene-recipe proof. The review also attributed marketing text visible only in seller reference IMAGE 1 to the generated candidate, although its observations reported no candidate captions or panels.

Generation recovery now records the exact scene-recipe SHA and requires matching recipe evidence before adopting a completed result across request identities. Legacy evidence remains recoverable under its exact original identity. A different recipe may receive a new request only after the prior request is definitively settled; unresolved, submitted and cancelled requests retain their stop guards. Historical files and receipts are retained. No negative review is promoted into an approval.

Review prompts and schema descriptions explicitly identify attachment 1 as comparison reference and attachment 2 as the publication candidate. Candidate-only text, layout, scene and photographic-proof checks ignore artwork visible only in the reference. Copied candidate captions/panels, fabricated efficacy/certification copy, wrong products/options, distorted geometry and unsupported actual publication claims remain blocked by the unchanged boolean parser and gates.

Recovery policy 7 identifies this changed algorithm; persistent no-progress budgets and cancellation/uncertain-output guards remain enforced. Follow-up scope is the single still-failed Minix material after the previous job finishes and the verified runtime is installed. Existing manuscripts and valid body photographs remain protected by a fresh file-hash baseline.

Sites failure details remain collapsed by default on the already published version 49, with an explicit failure-details summary. These additional changes affect the Windows generation/review runtime only.
