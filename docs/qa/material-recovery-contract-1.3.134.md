# Windows 1.3.134: explicit revision and source-photo recovery contracts

The installed 1.3.133 passed runtime, package, served-installer and native-connection checks. Two real partial-revision requests then failed without replacing the original manuscripts: a source-backed section-heading correction and six inaccurate photo-description corrections. Both logs recorded `REVISION_RENDER_SCOPE_AMBIGUOUS`, but the caller received a generic `QUALITY_REPAIR_REJECTED` message containing unrelated advisory quality feedback.

The exact reviewed corrections pass the current strict helper and the actual writer resolver against both saved documents in independent offline probes. The raw model candidates were not retained, so the precise rejected candidate boundaries cannot be reconstructed. Separate hypothetical probes reproduce refusal when a heading is inserted into the body or body paragraphs are merged across the old representation. These counterexamples are prevention evidence, not a claim to have recovered the actual failed responses.

The narrow follow-up strengthens the model contract for manual revisions: supply authoritative body paragraphs, validate a response array with the same paragraph count, and keep the existing body-string compatibility path. An explicitly requested section heading can change only within the selected section scope. Section-heading permission and whole-post-title permission are separate. Automatic quality convergence, strict render mapping, image-source policy, final image checks and approval reset remain in force.

Format and layout errors must retain their actual cause instead of being reported as a failure to improve a quality score. Tests must cover the actual writer, same-count paragraphs, heading-only body-byte preservation, unauthorized headings and titles, ambiguous or conflicting responses, unchanged image nodes and the final failure classification.

The live missing-draft workflow also found an incomplete source-photo search. The mat's first source photograph contained a promotional inset. Its recovery crop passed a coarse photo check but retained the inset and failed the complete prewriting gate. Recovery stopped there. An already collected seller photograph at source index 6 showed the complete selected mat in a single natural scene without an inset or explanatory text, but the first-five body-image limit and the early crop return prevented it from reaching the same final gate. Pixel inspection identifies it as a candidate, not an approved original.

Source recovery must search the verified seller-source pool independently of the body insertion count, prefer suitable original pixels before crops, and continue the bounded search when a coarse crop passes but the full gate rejects it. Every chosen image still needs the same product/option, provenance, hash and complete-photo checks. Provider quota and transport failures must propagate instead of creating repeated calls. No source or approval criterion is relaxed.
