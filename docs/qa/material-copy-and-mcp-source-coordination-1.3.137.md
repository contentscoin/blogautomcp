# 1.3.137 소재 부분 복구 및 MCP 원본 준비 순서

## 확인한 오류와 수정

- 거절된 대표 이미지의 실패 예산에는 본문·상품 근거만 들어가고, 실제 썸네일 문구가 들어가지 않았다. 따라서 잘못된 카테고리 문구를 수정해도 보완 버튼이 복구 작업에 들어가지 않았다. 거절된 대표 이미지 하나에만 완료된 원본·참조·레시피·현재 문구를 묶은 복구 입력을 추가한다. 본문 사진·원본 재수집의 예산과 과거 기록은 유지한다.
- 곶감 선물의 `구성·보관 확인` 문구가 사진으로 보관 성능을 증명한다는 주장으로 해석된 실제 검수 결과가 있었다. 해당 썸네일 테마만 `선물 전 체크`로 바꾸고 보관 조언은 본문에 남긴다. 다른 상품 카테고리와 승인된 사진을 일괄 변경하지 않는다.
- MCP 원고 제출은 원본 사진 배정을 비동기로 시작한 뒤, 응답용 참조 준비가 같은 판매자 캐시를 동시에 수집했다. 실제 상품 근거 감사 중 캐시 영수증 목록이 바뀌어 `IMAGE_CHANGED`가 발생했다. 기존 원본 배정 작업을 제한된 시간 동안 기다린 뒤 응답용 참조를 준비한다. 실패·취소·활성 소유권이 불확실하면 참조를 준비 중으로 반환한다.

## 유지하는 조건

- 저장된 원고와 정상 사진을 보존하고, 승인·발행 전의 기존 최종 검수를 유지한다.
- 동일한 거절 썸네일의 픽셀을 재적용하지 않는다. 완료 여부가 불확실한 이미지 요청은 재전송하지 않는다.
- 썸네일의 문구만 바뀐 경우에도 공개 이미지 처리 경로에서 파일·완료 영수증·참조·최종 검수를 확인한다. 문구 변경 자체는 승인 근거가 아니다.
- 발행 이력이 불명확한 소재는 중복 방지 보류를 유지한다. 이 수정은 발행·예약 작업을 시작하지 않는다.

## 검증 범위

- `verify-image-batch-progress.ts`: 실제 소재 준비 → 영속 복구 예산 → 공개 이미지 처리 경로를 연결한다. 변경 문구의 완료 원본 재사용과 동일 결과·참조 변경·미완료 요청·실제 텍스트 실패의 차단을 확인한다.
- `verify-shopping-thumbnail-copy.ts`: 곶감 문구와 다른 상품 카테고리의 계약을 확인한다.
- `verify-mcp-source-repair-coordination.ts`: 실제 스케줄러와 MCP 이미지 슬롯 함수 및 상품 근거 지문을 사용해 캐시 경합과 대기·실패·취소·다른 소유자의 상태를 재현한다.
- 새 회귀는 `test:material-regression`에 포함한다. 모의 검증은 실제 상품 사진의 승인 결과를 대신하지 않으며, 실제 승인과 배포는 별도 실행 증거로 확인한다.
