# 판매자 원본 최종 검토 소진 분류 보강

## 현장 근거

PC 1.3.125의 Bluefill 소재 보완 pilot은 기존 원고와 정상 사진을 보존하고 새 이미지 생성 없이 종료됐습니다. 현재 원본 진단에는 후보 19개, 초기 거절 12개, 최종 거절 6개와 최종 검토를 받지 않은 적합 제안 1개가 남았습니다. 그런데 이 결과가 `complete`로 저장되고 같은 입력의 완료 캐시에 재사용됐습니다. 따라서 원본 파일 자체의 부재로 결론 내릴 수 없습니다.

최종 거절 6개 중 4개는 원고의 구체적인 사진 장면 묘사 불일치 판정을 포함하며, 일부는 상품 식별 실패도 함께 포함합니다. 나머지 후보는 설명판·추가 문구·여러 장면 등의 형식 문제로 거절됐습니다. 남은 예비 후보의 실제 픽셀에도 설명 패널이 보이므로 해당 후보가 추가 검사를 통과하거나 소재가 승인될 것이라고 보장하지 않습니다. 원고 원문, 인증 정보와 토큰은 이 기록에 포함하지 않습니다.

## 변경 범위

- 미배정 파트에 최종 검토되지 않은 `proposed / reserve` 후보가 남으면 `incomplete`와 `SOURCE_REVIEW_INCOMPLETE`로 진단하며 완료 캐시에 저장하지 않습니다.
- 원본 검토 알고리즘의 메모리 캐시 키만 12에서 13으로 갱신합니다. 외부 이미지 복구 정책 10, 복구 예산과 승인 정책 정본 15파일은 변경하지 않습니다.
- 최종 픽셀 검사 6회 한도, 실제 거절 후보 제외, 선택 상품·옵션·단일 자연 사진 기준과 검증된 동일 바이트의 캐시 재사용을 유지합니다.
- 재수집·생성·발행·기존 원고/사진/복구 기록 변경은 이 수정 검증에서 실행하지 않습니다.

## 복구 경로 후속 과제

현재 `repair_photo_description`는 저장된 이미지 노드와 자산 SHA, 서버 finding 및 거절 기록에 연결된 사진만 처리합니다. 미배정 원본 후보의 임시 검사에서 나온 묘사 불일치는 이 연결이 없어 해당 경로를 직접 사용할 수 없습니다.

이번 현장 후보에는 상품 식별이나 형식 문제와 묘사 불일치가 섞여 있어 순수한 본문 묘사 문제로 확정할 안전한 대상이 없습니다. 따라서 미배정 후보 finding 복구 경로를 추가하거나 기존 검사 기준을 완화하지 않습니다. 별도 구현 시에는 상품·옵션·형식·텍스트 정책은 모두 통과하고 사진 묘사만 실패한 서버 판정에 한해 현재 소재 revision, SKU snapshot, 후보 바이트 SHA와 정확한 문장에 연결된 증거가 필요합니다. 원고 전체 재작성과 생성 사진 대체를 허용해서는 안 됩니다.

## 검증

실제 원본 검토와 최종 제안 검사 함수를 사용해 7개 적합 제안 중 6개가 최종 거절되고 1개가 미검수로 남는 반례를 재현합니다. 같은 명시적 호출에서도 완료 캐시를 재사용하지 않는지, 미검수 후보를 채택하지 않는지와 원고 작성 전 게이트의 코드 전파를 확인합니다. 이미 검증된 파트에 남은 불필요한 예비 후보는 정상 완료와 동일 바이트 캐시 재사용을 유지해야 합니다.

소재 보완 통합 회귀는 원본 배정 요청의 HTTP 422, 성공 응답의 상위 코드, 성공 응답의 오류 배열 세 경로에서 `SOURCE_REVIEW_INCOMPLETE`가 그대로 종료 원인으로 전달되는지 검증합니다. 이 경우 원고 전체 재작성, 원본 재수집, 새 이미지 생성, 재계획과 승인이 실행돼서는 안 됩니다.

- 변경한 TypeScript 3파일 ESLint: PASS.
- `verify-product-section-image-review`: PASS. 실제 함수의 7제안/6거절 반례, 완료 캐시 금지, 작성 전 코드 전파와 정상 원본 재사용을 포함합니다.
- `verify-scheduled-draft-workflow` (`tsx`): PASS. 원본 배정 세 응답 경로의 코드 보존과 재수집·생성·재작성·승인 중단을 포함합니다.
- `verify-shopping-prewrite-photos`, `verify-product-proposal-audit`, `verify-seller-original-source-recovery` (38개), `verify-material-image-recovery`: 모두 PASS.

워크플로 검사의 첫 `ts-node` 실행은 경로 별칭 모듈을 해석하지 못해 검사 시작 전에 종료됐으며, 기존 통합 검사 러너와 동일한 `tsx`로 실행해 PASS를 확인했습니다. 외부 인증·유료 생성·사용자 소재 변경은 실행하지 않았습니다. 수정본의 실제 PC 배포와 현장 재실행은 별도 릴리스 작업입니다.
