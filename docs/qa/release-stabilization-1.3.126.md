## 구현과 검증 범위

- 작성 계획을 상품 근거 → 절별 질문 → 조건부 판단 → 실제 사진 역할에 연결하고 PC·MCP에서 공유한다. 제목 후보는 5개이며 기존 정상 제목을 보존한다. 본문 설명 프레임·카드 금지와 썸네일 큰 문구 기준을 유지한다.
- 원본 검토 미완료와 실제 원본 부족을 구분한다. 같은 사진 바이트의 새 경로는 검토 결과를 현재 파일에 연결하며, 바이트·선택 조건이 달라지면 다시 검사한다.
- 최종 검사 한도에 걸려 미검수 예비 후보가 남은 결과를 완료 캐시에 넣지 않는다. 원본 검토 캐시 키는 126에서 13, 선택 문맥을 보강한 127에서 14다. 승인 정본 15파일과 외부 복구 정책 10은 그대로다.
- 원본 배정 뒤 남은 연출 슬롯의 `IMAGE_GENERATION_REQUIRED`를 구조화해 다음 제한된 보완 단계로 진행한다. 인증·원본 검토 미완료·결과 불명·알 수 없는 오류가 함께 있으면 중단한다. 실제 이미지 API 응답을 공통 워크플로에 연결한 회귀로 확인했다.
- 정확한 서버 검수가 지적한 ‘상자 사진’ 설명 한 문장을 현재 노드·사진 SHA·본문 문맥에 연결해 보완할 수 있다. 수치 사양·임의 외형 문장·인용 조각·잘못된 상품 식별·혼합 옵션·그래픽 판정은 수정 권한을 만들지 않는다.
- 실패 상세는 기본 접힘이며 펼치면 부족 슬롯·구분된 원인·다음 조치를 제공한다. 진행 중이면 대기, 결과 불명이면 기존 요청 조회, 게시·예약 상태면 해당 결과 확인을 안내한다.
- 현재 소재 준비 수와 과거 실행 결과를 구분한다. 최신 PC 조회의 준비 상태·시각을 확인한 `MATERIALS_LIST`만 현재 재고를 증명하며 저장된 작업 접수 영수증은 최종 완료를 의미하지 않는다.
- 게시 URL 존재와 전체 콘텐츠 검증을 분리한다. 본문·상단 고지·사진 수·순서·바이트·커넥트 링크·게시 시점 스냅샷을 대조하며 불일치·미확인은 자동 재발행하지 않는다.

루트·Sites 타입 검사와 production build, 해당 회귀·전체 CI를 확인했다. 126의 루트 CI 범위 lint는 오류 0건이며 당시 경고 21건은 별도로 남는다. Sites 54 전체 검사 205개, OAuth 회귀와 추가 반례, 배포 소스/아카이브 검증이 통과했다. 아카이브의 실제 비밀값 검사 패턴은 1개이며 일치 0개였다. 새 코드의 독립 검토는 실제 실패 반례와 거절해야 하는 경계를 검사했다.

## 실제 운영 확인

같은 52개 소재의 작업 전 현재 상태는 **준비완료 37개·차단 15개**였다. 과거 작업 기록의 **28개 통과·24개 실패**와 다른 기준이다. 배포 뒤 실제 ChatGPT MCP에서도 현재 37개와 과거 28개가 분리돼 조회됐다. 이 수치를 신규 최초 작성 성공률로 해석하지 않는다.

블루필 한 건의 실패 전용 보완은 기존 원고·사진을 보존하고 원본 배정 문제로 종료됐다. 이 시험에서 미검수 후보가 남아도 완료 캐시에 들어가는 결함을 발견해 수정했다. 같은 입력의 제한 예산을 다시 초기화하지 않는다.

곶감 한 건의 실제 MCP 시험에서는 원본 재배정 1건과 새 연출 사진 1건이 적용됐다. 최종 검사 후의 유효 장수 감소는 파일 삭제가 아닌 거절 이력에 따른 제외였다. 새 사진의 본문 외형 묘사 오류와 기존 사진의 카탈로그 옵션 해석 판정을 구분했고, 복구 응답 분류와 정확한 상자 사진 설명 finding을 추가로 수정했다. 옵션 부재만으로 사진 자체가 잘못됐다고 단정하거나 모델의 거절 boolean을 덮어쓰지 않는다.

기존 `65kg` 소제목은 수정 전 자료에도 있었으며 본문 근거는 `1.65kg`다. 실제 현재 작성·조립 함수의 `1.65kg`, `2.0L` 반례는 4개 모두 보존됐다. 현 코드 훼손 증거는 없고 해당 기존 절은 근거에 맞춘 개별 보완 대상이다.

기존 공개 글 한 건을 네이버에서 읽어 사진 7장 모두 게시 당시 원본과 SHA가 일치함을 확인했다. 하단 고지와 추가 본문 등 현재 계약과 다른 부분은 콘텐츠 불일치로 표시됐고 게시물 존재 상태는 유지했다. 새 글을 발행하거나 이 과거 글을 자동으로 재게시하지 않았다.

## 실패 전용 보완과 보존

작업 전 원고·manifest 72개와 기존 사진 SHA 571개를 고정했다. 첫 두 시험 이후 원고 변경 0건, 기존 사진 바이트 변경 0건, 시험 외 소재의 보호 대상 내용·사진 연결 변경 0건이다. 시험 대상의 사진 연결 변경은 별도로 기록했다. 전체 패키지 백업은 보완 전에 만들어진다.

남은 15개 중 결과 미확인 요청 1개, 같은 입력으로 이미 제한 보완이 실패한 블루필과 별도 조사 중인 곶감 2개를 제외한 **12개**가 조건부 보완 대상이다. 완성된 출력부터 재검토하며, 설치된 126과 최신 준비 상태를 확인하고 정상·진행·발행·예약·결과 불명 대상은 실행에서 제외한다. 클릭이나 시간 경과만으로 복구 예산을 갱신하지 않는다.

12개 보완은 15:18 UTC에 종료됐다. 준비완료 2개·실패 10개이며 실행 중인 항목은 없다. 15:22 UTC의 최신 PC와 실제 MCP 조회 모두 전체 52개에서 **준비완료 39개·차단 13개**를 반환했다. 과거 실행 28개 통과·24개 실패는 그대로 구분한다. 신규 작성 성공률이나 127 수정본의 복구 성과로 해석하지 않는다.

기존 사진 571개 모두 존재하며 원래 SHA를 유지한다. 비선택 59개는 원고·제목·사진 연결·출처·절·렌더 노드에 변경이 없다. 보완 대상 12개의 실제 백업도 원고와 기존 사진 SHA를 대조해 확인했다. 원고 71개는 현재 파일 그대로이며, 다른 한 건의 검수가 지적한 55자 문장과 공백만 수정됐다. 이 문장은 실제 검사 입력 사진·본문·finding을 복구 계획과 대조했고, 같은 사진으로 수정 본문을 재검사해 통과했다. 정상 문단과 다른 절은 유지됐으며 수정 전 원고도 정확한 백업에 보존됐다.

선택 대상의 사진 연결 변경은 실제 이후 거절 기록과 재검수·생성 작업에 대응했다. 원고 전체를 재작성하거나 기존 사진 파일을 삭제하지 않았다. 결과 불명 대상은 실행에서 제외했다. 기존 제한 예산을 초기화하거나 새 게시·예약을 요청하지 않았다.

남은 차단 사유에는 최종 사진 검사, 원본 배정 부족, 완료 캐시의 같은 썸네일 재채택, 원고 보완 소진, 구성 및 사진 묘사 보완이 있다. 검수 결과와 직접 확인한 이미지가 다른 사례는 판정 변동 가능성으로 구분하고 거절 boolean을 임의로 덮어쓰지 않는다. 실제 발견한 원본 검사 문맥·충돌 처리·썸네일 재채택 결함의 추가 소스 수정은 `docs/qa/source-audit-parity-1.3.127.md`에 기록했다.

## 127 설치 후 원본 배정 시험

127 설치 확인 후 한우 소재 한 건에서 원본 슬롯 하나만 복구했다. 설치 후 원고 재검사 메타데이터가 갱신돼 기존 계획 revision 가드가 전송 전에 중단됐고, 원고·출처·정상 사진·완료 영수증 불변을 확인한 뒤 이전 계획을 보존하고 현재 revision으로 연결했다. 이미지 복구 입력 서명과 기존 예산은 바꾸지 않았다.

16:21 UTC에 원본 배정 요청을 정확히 한 번 보내 16:24 UTC에 HTTP 200, 적용 1장·생성 0장·남은 원본 슬롯 0개로 완료됐다. 새 백업 112파일을 검증했고 원고·제목·출처·기존 사진 바이트·다른 이미지 4장·기존 완료 요청을 보존했다. 승인·새 발행·예약 요청은 없다.

직접 확인한 새 후보는 ‘꽃등심 200g’ 설명이 붙은 판매자 정보 카드였다. 본문은 1200g 세트에 관한 내용이며 자연 본문 사진 규칙과도 대조해야 하므로 배정 성공을 준비완료로 간주하지 않았다. 승인 요청을 보류하고 승인·생성·발행을 하지 않는 정본 사진 진단 검사로 확인했다.
