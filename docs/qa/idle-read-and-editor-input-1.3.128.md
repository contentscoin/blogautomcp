# Windows 1.3.128: 자동 조회 및 네이버 본문 입력 안정화

검증일: 2026-10-15. 범위는 Windows 프로그램 업데이트다. Sites 54와 기존 MCP 연결 설정은 유지한다.

## 수정한 문제

- 여러 화면의 소재 목록 조회를 한 피드로 공유한다. 자동 갱신은 저장된 검사 결과와 파일 메타데이터를 표시하며, 원고·사진·정책·서명키 원문을 다시 읽지 않는다. 유휴 상태에서는 60초 간격이고 창을 숨기면 요청을 중단한다.
- 명시적 소재 선택은 선택한 ID만 실제 바이트로 검사한다. 자동 목록의 revision은 표시용이며 승인·발행 권한으로 인정하지 않는다. 이 엄격 검사의 실패 결과도 같은 메타데이터 토큰의 임시 요약에만 반영해 보완 대상이 화면에서 사라지는 문제를 막았다.
- 이미지 진행 상태 조회에서 전체 미리보기와 사진 검사를 분리했다. 종료 시 미리보기는 한 번만 읽고, 작업 소유자 중단·불명 상태는 기존 판정을 유지한다.
- 한 건 보완 전에 모든 다른 소재를 재검사하던 경로를 해당 소재 검사로 줄였다. 이미 발행·예약되었거나 결과가 불명확한 소재의 제외 조건은 유지한다.
- 과거 발행 실패는 현재 소재 준비완료와 구분한다. 준비완료만으로 '이후 복구 완료'라고 표시하지 않고 발행 재시도 필요를 표시한다. 실제 발행·예약 상태가 확인돼야 발행 복구로 표시한다.
- 최근 10건의 `EDITOR_BODY_SCOPE_AMBIGUOUS (unscoped-visible-text)` 기록에는 본문 0자와 삽입 메뉴의 접근성 안내 '추가할 컴포넌트를 선택하세요.'가 있었다. Naver 공개 SmartEditor 1.78.1 소스에서 이 문구의 `.se-insert-menu` 소유 관계와 실제 `.__se_placeholder` 클래스를 확인했다. 해당 UI만 제외하며 일반 본문·범위 밖 내용은 계속 검사한다.
- 제목 뒤 Tab으로 이동하던 가정을 제거했다. 유일한 빈 본문을 확인해 선택한 후 실제 텍스트 컴포넌트와 입력 버퍼를 확인한다. 제목·이미지·링크 선택, 다중 편집기·버퍼, 서식 변경 중 문단 이동은 차단한다. 툴바가 포커스를 가져갔을 때에는 같은 본문·버퍼에만 포커스를 복원하고 커서 위치는 옮기지 않는다.

## 검증

- 새 자동 조회·선택 API·공유 피드 회귀 71개 및 경량 진행 조회 경계 검사 통과.
- 전체 소재 회귀 24종, 실패 소재 재작성·버튼 검사, 기존 본문 검사 19개·실제 본문 판독 함수 58개·렌더 순서 5개 통과.
- 실제 Chromium에서 생산 코드의 직렬화 함수와 타이핑을 사용하는 오프라인 회귀 25개 통과. 네트워크는 차단한다. `npm run test:naver-editor-body-browser`는 생산과 같은 ts-node를 사용한다.
- 독립 검토가 발견한 보완 대상 누락·이미지 선택 타이핑·서식 중 문단 이동 3건을 수정하고 최초 반례로 재검증했다. 실제 사진 변조·승인 영수증 삭제·결과 불명·잠금 중 원고 변경은 발행 POST에서 409로 거절됐고 작업 저장·발행 호출은 0회였다.
- 전체 TypeScript 통과. CI 기준 lint 오류 0개·기존 경고 23개. 첫 CI의 테스트 fixture DOM 타입 오류 2곳은 수정했고 전체 TypeScript와 Chromium 검사를 다시 통과했다.
- 이후 CI에서 발견한 기존 로그인 화면 VM 로더의 TS 의존성 누락도 수정했다. 실제 폴링 모듈을 로드하며 검증을 생략하지 않는다. 로그인 상태 100개와 로그인·쇼핑 연결 검사, 숨김 중단·중복 방지·취소·늦은 응답 무시·타이머 정리 검사를 통과했다.
- 이전 승인 정본 15개 파일과 엄격한 승인·발행 판정은 수정하지 않았다.

## 데이터 보존 및 실환경 범위

변경 전 원고 80개, 사진 3,945개(3,384,761,676바이트), 생성 요청·참조·체크포인트 기록 567개를 해시로 기록했다. 운영 데이터의 경로·원문·비밀값은 공개 문서에 포함하지 않는다.

자동 조회 변경 전 설치된 1.3.127의 `jobsOnly=1` 응답은 6,173ms였다. 수정된 요약 모듈을 실제 저장된 소재 80개에 적용한 읽기 전용 검사에서는 원고·사진 원문 읽기 0회였다. 서로 다른 검증 범위의 수치이므로 이를 동일한 엄격 검사 속도 향상으로 해석하지 않는다.

실제 네이버 편집기에 글을 입력·저장·재발행하거나 새 이미지를 생성하지 않았다. 오프라인 DOM·키보드 검사는 실계정의 실제 발행 성공을 보장하지 않는다. 기존 실패 10건의 실행 기록도 보존한다.
