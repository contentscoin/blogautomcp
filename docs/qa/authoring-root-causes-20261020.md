# 최초 작성과 보완의 반복 실패 원인

2026-10-20 점검 대상은 직전 보완 작업 6개 중 실패한 5개다. 개별 원고 수정이나 실패 상태를 준비완료로 바꾸는 작업은 수행하지 않는다. 기존 원고·사진·생성 요청 기록과 승인·발행 전 검수는 보존한다.

## 실제 로그로 확인한 원인

| 관찰 | 실제 원인 | 제거할 조건 |
|---|---|---|
| 현미경·노트북·러닝조끼의 `IMAGE_RESUME_REQUIRED` | 저장된 상품·본문 바인딩과 참조 사진 픽셀은 일치했다. 같은 사진을 재수집하면서 `retrievedAt`이 포함된 출처 기록을 덮어썼고, 요청에 저장된 출처 기록 SHA가 달라졌다. | 출처 원본은 불변으로 보관하고 최신 재수집 시각을 별도 관측으로 기록한다. 과거 출처가 손실됐으면 실제 저장 SHA와 일치하는 원문을 확인해야 복구한다. 현재 파일을 다시 서명하는 방식은 사용하지 않는다. |
| 이어폰·내의의 형상 검수 재실패 | 완료된 기존 생성 결과를 다시 검수하고 있었다. 새로 생성한 결과가 다시 실패했다는 증거는 없었다. 최초 프롬프트에는 착용 원본에 없는 단독 물체·평면 배치·보이지 않는 허리밴드를 요구하는 지시가 들어 있었다. | 상품 범주보다 실제 참조의 착용 상태·관찰 면·가려진 부분을 우선한다. 원본이 뒷면이나 허리밴드를 보여 주지 않으면 그 형태를 새로 요구하지 않는다. |
| 글의 사진 계획과 생성 역할이 불일치 | 생성 사진 순번에 전체 본문 섹션 번호를 사용했다. 중간의 원본 사진·사진 없는 문단 때문에 첫 생성 슬롯이 세 번째 장면 지시를 받거나 같은 역할이 중복됐다. | 새 요청은 실제 생성 슬롯 순서로 역할을 정한다. 전송된 과거 요청은 당시 순번·프롬프트로만 복구한다. |
| 보완 시 새 외형 문장과 기존 사진이 충돌할 수 있음 | 최초 작성은 검증 원본과 사진 문맥을 전달했지만 보완 작성은 그 픽셀·문맥을 누락했다. | 보완도 현재 배정한 검증 원본과 동일한 글쓰기 계약을 사용한다. 사진이 없거나 바뀌면 과거 관찰을 새 사실로 승계하지 않는다. |
| PC와 ChatGPT 직접 이미지 적용의 불일치 | 생성은 원본·형상·식별면 최대 3장을 사용하지만 외부 첨부·적용 경로 일부는 최대 2장만 허용했다. | 3장 계약과 각 참조 역할·순서를 양쪽에 적용한다. 실제 응답에 전체 참조를 첨부하지 못한 슬롯은 준비완료로 알리지 않는다. |

처음에는 본문 변경이 이번 세 건의 요청 바인딩을 바꿨을 가능성도 조사했다. 실제 함수로 재계산한 바인딩은 일치했으므로 이번 사례의 직접 원인으로 확정하지 않았다. 본문 변경과 전송 중 요청의 충돌은 별도의 보호 경계로 유지한다.

## 생성과 복구의 공통 경계

- 사진의 출처와 상품·옵션 동일성 검토를 실제 생성 전에 수행한다. 출처 기록은 동일성 승인이나 사진 사용 권한을 뜻하지 않는다.
- 관찰한 착용 상태·식별 면을 유지한 채 배경·빛·거리로 자연스러운 변화를 만든다. 뒷면·구조·문구를 추측해서 다양성을 채우지 않는다.
- 진행 중이거나 전송 여부가 불명확한 요청은 새로 보내지 않는다. 기존 요청의 입력·기록·결과만 복구한다.
- 확정 완료 결과가 실제 비교 검수에서 거절됐으면 그 출력·참조·본문·요청을 묶어 기록한다. 개선된 참조·장면 계획으로 전환할 근거와 기존 요청의 종료 증거가 모두 있어야 제한된 새 시도를 허용한다.
- 이미 정상인 사진·본문을 다시 만들지 않는다. 새 시도가 실패해도 기존 원고·정상 사진·과거 작업 결과를 지우지 않는다.
- 최종 사진의 형상·브랜드·선택 옵션, 사진과 실제 게시 문장의 일치 및 승인 검사는 계속 수행한다. 지시문 개선을 검수 통과로 간주하지 않는다.

## 검증의 의미

회귀 시험은 동일 사진의 재수집, 실제 과거 출처 SHA의 복구, 잘못된 출처·픽셀의 차단, 착용 사진에서 가려진 부위 생성 금지, 생성 슬롯 순서, 최초 작성·보완의 사진 문맥, ChatGPT 3장 첨부와 잘못된 해시·순서 거부를 검사해야 한다.

오프라인 시험은 새 사진의 실제 품질이나 전체 소재의 승인 준비 완료를 증명하지 않는다. 실제 재생성 성공률과 종단 처리 성공률은 이후 동일 기준의 실사용 결과로 따로 측정한다. 이번 작업에서 사용자 원고를 수동 수정한 결과를 시스템 개선의 증거로 사용하지 않는다.

기존 실패 자료를 읽어 격리한 재현에서는 러닝조끼의 과거 출처 기록 두 개가 원래 SHA와 정확히 일치하는 백업에 남아 있었고, 그 원문으로만 참조를 복구했다. 현미경·노트북은 해당 원문을 찾지 못해 자동 해제하지 않았다. 이어폰·내의의 오래된 요청은 완전한 생성 문맥이 저장되기 전 형식이어서 종료된 파일만으로 다른 프롬프트를 재전송하지 않는다. 이 보류를 새 작성 경로의 예방 수정이나 소재 준비완료와 혼동하지 않는다.

ChatGPT 직접 이미지 작업에서 참조가 다른 슬롯은 `post_get_draft(referenceSectionId)`로 그 슬롯만 조회한다. 실제 첨부 순서가 슬롯의 참조 해시 순서와 정확히 일치해야 생성 가능으로 표시한다. 새 슬롯 조회와 3장 참조 적용은 PC 1.3.143 이상에서만 접수하며, 구버전의 기존 1~2장 호출은 호환을 유지한다.
