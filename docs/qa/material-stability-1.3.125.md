# 소재 준비 안정화 · 1.3.125

2026-10-13 KST. 상품 근거·절별 질문·조건부 판단·사진 역할을 같은 작성 계획으로 묶고, 원본 판정 누락과 사진 결과 불명을 구분하는 보강이다. 정상 원고와 사진은 보존하며, 실제 복구는 현재 실패 대상만 선택한다.

## 수정과 반례

- 원본 검토의 `incomplete`/`INVALID_REVIEW`를 실제 원본 부족이나 사진 거절로 오인하지 않는다. 원본 슬롯은 검증 판매자 사진을 재배정하고 AI로 대체하지 않는다.
- 같은 SHA의 사진이 다시 수집돼 경로만 바뀌면 현재 파일에 검토 결과를 재결합한다. 파일 바이트·선택 옵션이 바뀌면 다시 검토한다. 캐시 객체를 호출자가 수정할 수 없게 한다.
- 사진 3장의 서로 다른 역할과 원고의 질문·근거·판단을 PC·MCP 공통 하네스에서 사용한다. 제목 후보는 5개로 늘리고 기존 정상 제목을 보존한다. 본문 프레임·설명 카드 금지와 썸네일 큰 문구 기준은 유지한다.
- 복구 정책 10은 실제 알고리즘 변경에 대한 한 번의 제한 복구 기회다. 시간·클릭만으로 예산을 갱신하지 않고, 기존 결과 불명 요청은 조회 없이 재전송하지 않는다. 승인 정책 지문 소스 15개는 변경하지 않았다.
- 실패 로그는 기본 접힘을 유지하고, 펼쳤을 때 부족한 슬롯·원인·다음 조치를 제공한다. `SEMANTIC_REJECTION`만으로 사진 자체 결함이라고 단정하지 않는다.
- 진단 안내와 실제 상품 상태도 일치시킨다. 작업 중이면 대기, 결과 불명이면 기존 결과 조회, 게시·예약 완료면 해당 결과 조회를 안내한다. 저장된 준비완료 진단이나 부족 슬롯의 생성 안내가 이 상태 가드를 덮어쓰지 못하며 캐시 객체를 변경하지 않는다.
- 실제 MCP 읽기에서 과거 실행 28/52가 현재 37/52처럼 갱신되지 않던 문제를 확인했다. 최근 PC `MATERIALS_LIST` 조회 시각과 현재 소재 상태를 확인하고 현재 준비 수와 과거 실패 결과를 분리한다. 저장된 작업 영수증은 현재 준비완료로 선언하지 않고 재조회를 안내한다.
- 발행 URL 존재와 전체 콘텐츠 검증을 분리한다. 제목·상단 고지·정규화한 본문·사진 수와 순서·사진 바이트·커넥트 링크를 대조하며, 미검증·불일치 상태는 자동 재발행하지 않는다. 예약 접수와 실시간 목록/예정 시각 후 게시 확인도 구분한다.

독립 검토에서 본문 밖 가짜 제목, 승인하지 않은 추가 문장, `opacity:0.0` 숨김 본문을 허용하던 반례를 수정했다. 실제 공개 네이버 글은 `se-viewer` 안의 제목과 본문이 형제 구조임을 확인하고 호환성을 추가했다. HTTP 200·게시물 ID 일치·이미지 7장·커넥트 카드 2개를 확인했다. 이 DOM 검증은 해당 사진 전체 SHA 대조나 실시간 예약 목록 확인과 구분한다.

15개 복구 이력의 읽기 전용 대조에서 현 입력에 대한 정책 9 예산 소진은 9개 상품·10단계(원본 재수집 4, 거절 사진 복구 5, 재기획 1)였다. 정책 10 현 입력 소진은 0개였다. 15개 모두 같은 원인이나 예산 소진이라고 단정하지 않는다.
