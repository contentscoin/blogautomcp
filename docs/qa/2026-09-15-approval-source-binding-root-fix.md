# 소재 승인·이미지 결속 근본 수정 보고서

작성일: 2026-09-15  
대상: 쇼핑커넥트·여행커넥트 소재 준비, 이미지 보강, 승인, MCP 일괄 작업, Windows 자동 업데이트

## 확인된 사용자 장애

CRNK 바디드라이어 소재 `cc67d605-96cf-4e2a-ac37-8d7324c263d9`는 원고 점수와 이미지 준비 상태가 서로 다른데도 한 번의 품질 실패로 합쳐졌다. 원고는 96점에서 보강 후 100점 후보가 만들어졌지만, 본문 네 파트의 이미지가 비어 있어 최종 조립이 실패했고 시스템은 합격한 원고까지 되돌린 뒤 `QUALITY_REPAIR_EXHAUSTED`로 기록했다.

저장 패키지에는 대표 이미지 한 장과 판매자 페이지에서 수집한 미배정 원본 일곱 장이 있었다. 네 파트에 맞는 공식 이미지도 실제로 존재했지만, 후보 파일 순서와 모델에 표시한 번호 순서가 달라 다른 파일 해시가 선택됐다. 그 결과 안전한 원본이 있어도 `PRODUCT_CUTOUT_REQUIRED`가 반복됐다.

## 근본 원인

1. 원고 합격과 이미지 조립 합격을 하나의 롤백 단위로 처리했다.
2. 텍스트만 보강해도 이미지 의도와 작업 식별자가 불안정해져 완료 이미지를 다시 생성했다.
3. 판매자 이미지의 모델 입력 순서를 정렬하면서 응답 번호를 원래 배열에 적용해 잘못된 파일을 선택했다.
4. 첫 후보 묶음만 검사해 판매자 페이지 뒤쪽의 기능 근거 이미지가 가려졌다.
5. 일반 상품 사진과 기능 근거 이미지를 같은 등급으로 취급했다.
6. 대표·본문 및 본문 파트 사이에 같은 SHA를 중복 배정할 수 있었다.
7. 구형 이미지의 목적·슬롯·출처 검토 기록이 현재 원고와 다른데도 승인 계산에 포함될 수 있었다.
8. 프로세스 내부 잠금만 있어 데스크톱과 MCP가 동시에 같은 매니페스트를 덮어쓸 수 있었다.
9. Codex 인증·버전·모델 오류가 품질 수렴 오류로 바뀌어 같은 작업이 반복됐다.
10. 공용 제공자 장애도 상품별 오류로 보아 10개 모두 같은 실패를 실행했다.
11. MCP 소재 결과는 사람이 읽는 오류 문자열만 저장해 호출자가 재시도 여부를 판단할 수 없었다.
12. 긴급 복구 스크립트가 한 장의 일반 상품 사진을 여러 기능 파트에 반복 합성할 수 있었다.

## 수정 방향과 구현

### 원고와 이미지 단계 분리

- 보강 원고가 편집 품질을 통과하면 이미지 조립이 미완료여도 개선된 원고를 저장한다.
- 이 경우 `COMPOSITION_REPAIR_REQUIRED`를 반환하고 `QUALITY_REPAIR_EXHAUSTED`로 오인하지 않는다.
- 텍스트만 바뀐 파트는 현재 목적이 같은 기존 이미지를 보존한다. 목적이 실제로 달라진 슬롯만 교체 대상으로 만든다.
- 발행 단계는 저장·승인된 원고와 이미지만 사용하며 새 이미지 생성을 시작하지 않는다.

### 판매자 이미지의 의미 검증과 원자적 결속

- 모델에 보낸 후보 순서를 그대로 유지해 응답 번호와 파일 SHA가 일치하게 했다.
- 로컬 후보와 판매자 URL 후보에 별도 수집 한도를 주고 전체 후보를 여러 묶음으로 검사한다.
- 파트 전체를 한 번에 일대일 배정해 같은 사진이 여러 파트의 근거로 계산되지 않게 했다.
- 제품 소개 파트에는 검증된 일반 상품 사진을 허용하고, 기능 파트에는 해당 기능이 실제로 보이는 `feature-evidence`만 허용한다.
- 대표·본문 전체에서 SHA를 한 번만 인정하고, 현재 `sectionId`, canonical `slotId`, `imageIntent`, `sourceReview`가 모두 일치해야 승인한다.
- 구형 슬롯·의도·출처 검토 기록은 미완료로 판정하고 자동 교체 계획에 포함한다.
- 판매자 원본 우선 복구가 가능한 경우 브라우저 이미지 생성을 실행하지 않는다.

### 동시 실행과 오류 의미

- 파일 기반 소유권 잠금, PID, owner token, heartbeat, stale owner 회복을 추가했다.
- 매니페스트를 쓸 때마다 소유권을 다시 확인해 늦게 도착한 결과가 새 초안을 덮지 못하게 했다.
- Codex 인증, 모델 비호환, 일시 장애, 시간 초과를 서로 다른 코드로 보존하고 원인 체인을 API와 MCP까지 전달한다.
- 인증·모델 비호환·브라우저 연결·공용 제공자 장애는 첫 실패 후 같은 10건 작업의 나머지를 중단한다. 상품별 시간 초과와 일시 오류는 다른 상품 처리를 계속한다.
- MCP 소재 결과에는 기존 오류 문구와 함께 안전한 구조화 오류 코드를 저장한다.

### 상품 근거와 설치 환경

- 한국어 OCR을 포함한 상품 상세 근거 추출을 추가하고 한국어·영어 Tesseract 자료를 설치본에 포함한다.
- 연결된 부정 표현이 여러 기능에 걸릴 때 모든 기능에 부정을 적용하되, 명시적으로 긍정된 기능은 보존한다.
- Codex SDK와 Windows CLI를 0.154.0으로 고정해 `gpt-6-astra`의 구형 Codex 비호환을 해소한다.
- 수동 복구 경로도 일반 승인 경로와 같은 슬롯·의도·출처 검사를 통과해야 하며, 불가능하면 원본 매니페스트로 롤백한다.

## 검증 현황

다음 검사는 외부 이미지 생성 없이 통과했다.

- TypeScript 타입 검사와 Next.js 프로덕션 빌드
- 원고 품질·수렴·저장 원고 보존 검사
- 쇼핑·여행 구성 계약과 파트별 최소 이미지 검사
- 후보 순서, 판매자 URL 후보 고갈 방지, 기능 근거 이미지 등급 검사
- 대표·본문 SHA 중복, 오래된 intent/slot, 출처 검토 위조 차단 검사
- 이미지 중단·재개·시간 제한·동일 결과 차단 검사
- 프로세스 간 잠금, heartbeat, dead owner 회복 검사
- 10건 소재 준비와 저장 소재만 사용하는 예약 흐름 검사
- MCP 전달 32개 및 MCP 소재 계약 검사
- 자동 업데이트 관리자 검사

전체 저장소 ESLint에는 기존 CJS 검사 파일의 `require()` 규칙 등 기준선 오류가 남아 있다. 이번 변경 대상 TypeScript 파일은 오류 없이 검사했으며 경고만 남아 있다.
