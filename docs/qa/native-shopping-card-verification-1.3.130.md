# Windows 1.3.130: 실제 쇼핑 상품 카드의 사후 판독

검증일: 2026-10-15. 테팔 글은 1.3.129에서 이미 한 건 발행됐다. 이 보강에서는 같은 게시글을 읽어 확인하며 추가 발행·예약·편집·이미지 생성은 하지 않는다.

## 실제 원인과 변경 범위

네이버의 실제 `se-shopping-connect` 카드 미리보기 2개를 기존 사후 판독기가 일반 본문 사진으로 셌다. 정상 본문 사진은 5장이지만 7장으로 읽고 카드 설명까지 본문에 섞어 `unsupported-image-wrapper`를 반환했다. 실제 발행 영수증과 URL은 확인됐으나 자동 본문 검증은 보류된 상태였다.

관찰한 닫힌 컴포넌트·섹션·단일 링크·카드 내용·미리보기·상품 정보의 직접 소유 구조만 상품 카드로 인식한다. 클래스 하나만으로 이미지나 문장을 제외하지 않는다. 형태가 다르거나 숨겨진 요소, 추가 사진·링크, 잘린 구조, 메타데이터·상품 번호·href가 다른 경우는 계속 거절한다.

저장된 승인 단축 URL과 네이버 카드의 실제 제휴 URL은 표현이 다르다. 승인된 정확한 HTTPS `naver.me` URL의 수동 307 응답 Location이 해당 카드의 메타데이터 URL과 문자열로 일치할 때만 원래 URL의 별칭을 연결한다. 요청은 중복 제거·전체 4초·고정 호스트·URL/응답 상한으로 제한하고 제휴 목적지는 방문하지 않는다. 알 수 없는 리다이렉트나 다른 상품 URL은 기존 미확인 판정을 유지한다.

승인 정본 15개, 제출 원고·사진, `verifyPublishedPostContent`의 제목·상단 고지·본문 전체/순서·사진 개수/위치/원본 SHA·카드 링크/순서·소재 revision 판정은 유지한다. 이 공개 HTML 판독과 검증 경로는 승인 정책의 원본 15개 밖에 있으므로 정상 이미지 승인 영수증을 무효화하지 않는다.

## 배포 전 실제 글 검사

기존 생산 `probePost`, 제출 snapshot 판독, 원본 이미지 다운로드와 검증 함수를 실제 글에 실행했다. 게시글 1회·단축 링크 1회·사진 5회의 GET을 사용했고 제휴 목적지·발행/편집 요청은 0회다.

- 본문 사진 5/5가 제출 snapshot 원본 SHA256과 정확히 일치했다.
- 제목·상단 고지·본문 순서·사진 수·사진 원본·상품 카드·게시물 identity·소재 revision의 8개 판정이 모두 통과했다.
- 이 결과는 아직 배포 전 소스의 읽기 전용 검사이며, 설치본 MCP 검증은 별도로 기록한다.

기존 본문 검증과 새 판독·리다이렉트 반례 43개, 실제 verify route를 사용하는 오프라인 통합 검사, 전체 TypeScript가 통과했다. 변경 파일 lint 오류·경고는 모두 0개다. 독립 검토의 45개 반례에서도 새 차단 결함은 발견되지 않았다. 사진 SHA가 불명확하거나 달라지면 이전처럼 미확인으로 남기며, 다른 게시물·원고 추가·카드 이동·위조 메타데이터·외부 링크를 성공으로 인정하지 않는다.

## 보존 기준과 완료 기록

1.3.130 기준은 원고 80개, 사진 3,960개(3,406,057,285바이트), 생성 관련 기록 569개다. 1.3.129 시작 시의 기존 사진 3,958개는 별도 감사에서 모두 보존됨을 확인했으며, 두 파일은 별도로 진행되던 곶감 작업에서 추가됐다. 해당 변경을 삭제하거나 과거 기준으로 되돌리지 않는다.

소유 회귀·독립 검토·패키지·설치·실제 MCP 사후 검증의 최종 결과는 완료 후 기록한다.
