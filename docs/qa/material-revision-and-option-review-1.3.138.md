# 1.3.138 소재 원고 보존 및 옵션 검수 보강

## 실제 발견 사항

1. `repair_photo_description`이 기존 package revision의 `post.md`를 덮어써 역사 manifest의 원고 지문과 실제 파일이 달라졌다. 현재 canonical manifest와 수정본은 일치했으며, 기존 원고는 공식 workflow 백업에 남아 있었다. 원래 실패 증거를 삭제하거나 비교 기준을 새로 잡아 정상으로 표시하지 않는다.
2. 판매 카탈로그에서 구입 옵션을 확정하지 않은 상태의 기획 지시가 최종 사진 검수에서 확정된 대체 SKU 지시로 해석됐다. 실제 같은 판매 구성의 외형, 구매 옵션의 포함·수량 증명, 사진이 사실을 입증한다는 본문 주장을 구분할 필요가 있다.

## 보존 및 검수 조건

- 사진 설명 수정은 새 immutable package revision으로 저장한 뒤 현재 pointer를 전환한다. 기존 원고·역사 manifest·정상 이미지와 배치는 보존한다.
- 실패·경합 시 이전 현재 pointer와 기존 revision을 유지한다.
- 이미 손상된 역사 원고는 현재 수정본을 새 revision에 먼저 보존한 후, 원래 manifest 지문과 정확히 일치하는 공식 백업에서만 복원한다. 백업·실패 이력은 수정하지 않는다.
- 실제 상품·SKU·확정 옵션 불일치, 불명확한 구성품 식별, 무근거 포함·수량·성능 단정, 설명 프레임과 본문 이미지 추가 문구는 계속 차단한다.
- 검수 결과의 boolean을 사후 보정하거나 특정 상품을 예외 승인하지 않는다. 승인·발행 전 최종 픽셀 검수는 유지한다.

## 운영 확인 범위

원래 실패 10건 중 이미 준비된 소재는 다시 작성하지 않는다. 남은 단계만 처리하며, 과거 발행 결과가 불확실한 소재의 보류를 우회하지 않는다. 블로그 발행·예약은 이 작업 범위에 포함하지 않는다.

실제 배포·설치·소재 결과 및 보존 비교는 별도 release 증거로 확인한다. 오프라인 회귀 통과만으로 실제 소재 승인 완료를 선언하지 않는다.

## 배포 전 로컬 검증

전체 타입 검사, 변경 파일 lint, 소재 회귀 29종이 통과했다. 실제 PATCH 경로의 immutable 저장 회귀 9건과 최종 이미지 검사 175건(분류·조언·배너 관련 신규 반례 16건 포함)을 확인했다. 별도 복원 helper는 격리 8모드를 검증한 뒤 한 건에만 적용했으며, 현재 수정본·역사 원고·공식 백업의 지문을 각각 확인했다.

정책 문구 변경은 기존 승인 지문을 무효화하므로, 이전 준비완료 개수를 배포 후 결과로 재사용하지 않는다. 정상 원고·사진은 다시 만들지 않고 공식 최종 승인 검사로 현재 정책의 준비 상태를 확인한다.
