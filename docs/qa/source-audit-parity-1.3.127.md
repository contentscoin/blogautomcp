# 원본 선정 문맥과 실패 진단 보강

2026-10-13. 기존 원고·정상 사진·정상 검수 영수증을 보존하는 추가 Windows 수정이다. Sites 자동 갱신 동의 화면은 별도로 배포한 버전 54다. 이 기록만으로 설치·운영 성공률을 증명하지 않는다.

## 실제 실패에서 확인한 원인

동일한 판매자 정보 카드의 이미지 바이트가 원본 선정의 최종 검사에서는 통과하고, 게시 전 검사에서는 설명 문구 때문에 거절됐다. 세 사례에서 파일·첨부 이미지 바이트가 동일했으므로 이미지 교체나 파일 유실로 설명할 수 없었다. 앞 단계에는 선택 상품의 스냅샷·수집 갤러리 비교 문맥이 빠져 있었다. 정보 카드 자체의 자연 사진 규칙 위반은 실제 결함이며 규칙을 완화하지 않는다. 모델 판정 변동이 완전히 사라졌다는 주장도 하지 않는다.

다른 원본 선정 완료 응답은 같은 후보·파트를 적합 목록과 미선택 목록에 동시에 넣었다. 원래 파서는 그 충돌로 전체 검토를 실패시켰다. 미선택 행을 지워 적합 판정만 채택하는 방식은 안전하지 않다.

최종 검사 후 원본 교체까지 실패하면 처음 사진 오류가 다시 반환돼 교체 응답의 구체적 실패 원인과 해당 절 정보가 가려졌다. 사진 묘사 수정 권한이 없는 실제 사진 결함에서는 sectionIds도 비어 있었다.

## 수정

- 원본 선정의 최종 검사에 게시 전 검사와 같은 정본 스냅샷·상품 ID·수집 폴더·스냅샷 ID와 후보 원본 힌트를 전달한다. 최초 작성의 원본 사전 검사와 기존 원본 복구도 같은 문맥을 사용한다.
- 원본 선정 캐시 키 14에 선택 문맥과 수집 기록·실제 비교 사진 바이트를 포함한다. 부분 문맥·스냅샷 불일치·검사 도중 변경은 이전 판정을 재사용하지 않는다.
- 완료된 응답에서 충돌한 후보·파트 조합만 미검토로 격리한다. 정상 제안과 실제 픽셀 탈락은 그대로 보존한다. 충돌 조합은 배정·최종 검사·추가 후보 검토에 다시 진입하지 않는다. 해당 파트를 다른 정상 후보가 최종 검사까지 통과하면 사용할 수 있다. 미충족 파트에 충돌이 남으면 검토 미완료로 반환하며 완료 캐시에 넣지 않는다.
- `SOURCE_REVIEW_CONFLICT`를 실패 슬롯부터 실제 HTTP 응답까지 유지한다. HTTP 200에 이 코드만 있고 오류 배열이 빠져도 추가 생성·승인·재계획을 시작하지 않는다. 생성 허가나 복구 예산 갱신 사유로 사용하지 않는다.
- 최종 승인 래퍼에서 정확히 검사한 렌더 노드 인덱스와 파일 경로가 일치할 때만 진단용 sectionId를 붙인다. 별도의 사진 묘사 finding이나 수정 권한을 만들지 않는다.
- 최초 게시 전 사진 오류와 교체의 구체적 원인을 제한된 코드 체인으로 함께 기록한다. 원래 오류·HTTP 상태·검사 배열은 유지하며 복구 응답 원문·인증값은 작성 참고 자료에 넣지 않는다.

정본 사진 정책 15파일은 1.3.126과 원시 SHA가 모두 동일하다. 진단 필드를 별도 래퍼에 두어 로그 수정 때문에 정상 사진 검수 영수증을 전부 무효화하지 않는다. 외부 이미지 복구 정책은 10을 유지하며 기존 결과 불명 요청과 같은 입력의 소진 예산을 초기화하지 않는다.

## 검증

완료 응답의 11개 제안·5개 실제 거절·1개 미선택 반례에서 충돌 조합 하나만 격리하고 다른 정상 제안·거절을 보존했다. 충돌만 남은 필수 파트는 추가 모델 호출이나 생성 없이 차단됐다. 같은 문맥에서 공통 최종 검사 프롬프트·첨부 SHA가 동일하고, 잘못된 스냅샷은 모델 호출 전 중단함을 확인했다.

스냅샷·옵션·수집 기록·사진 바이트 변경, 실제 생성 함수 → 이미지 API → 로컬 HTTP 호출의 코드 전달, 정확한 노드 진단 바인딩, 기존 오류와 원인 보존 및 코드 단독 성공 응답의 중단 반례가 통과했다. 일반 루트 TypeScript 검사와 CI 범위 lint는 오류 0건이며 lint 경고 23건은 별도로 남는다. 전체 소재 회귀 24종과 최종 변경에 영향을 받은 복구·실패 참고·워크플로 회귀를 확인했다.

범위를 넓힌 전체 `scripts` lint에서는 기존 CJS·임시 스크립트의 require 규칙 오류가 남는다. scripts 전용 TypeScript 설정의 기존 ES2023/JSX 오류도 별도 한계이며, 이를 변경한 검사 대신 일반 루트 타입 검사와 실제 CI 범위를 사용한다.

소스 검증과 실제 배포·현재 소재의 준비 상태는 구분한다. 설치파일·배포 후 운영 결과와 데이터 보존 확인은 최종 배포 기록에 추가한다. 신규 최초 작성 성공률이나 무조건 한 번에 복구된다는 보장은 이 회귀로 증명하지 않는다.
