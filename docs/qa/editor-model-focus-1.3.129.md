# Windows 1.3.129: 실제 네이버 입력 커서 검증

검증일: 2026-10-15. Windows 프로그램의 본문 입력 위치 확인을 수정한다. 기존 원고·사진을 사용하며 승인·발행 전 최종 검사는 유지한다.

## 확인한 원인과 수정

1.3.128의 오프라인 선택 상태 가정은 실제 SmartEditor 1.78.1과 달랐다. 실제 본문에 커서가 있어도 `.se-is-selected`가 없었으며, Enter 후 숨겨진 브라우저 Range는 이전 문단에 남았다. 서식 적용은 같은 문단을 유지하면서 컴포넌트 ID를 새로 만들기도 했다. 이 때문에 정상 입력을 `EDITOR_BODY_FOCUS_UNCONFIRMED`로 중단했다.

실제 편집기에서 확인한 읽기 전용 커서 모델과 키보드 입력 버퍼를 연결한다. 지원 버전·유일한 편집기·버퍼의 실제 본문·접힌 선택의 두 끝점·컴포넌트/문단/노드의 DOM 소유 관계와 ID 중복 여부를 확인한다. 제목·이미지·다른 입력창·충돌하는 선택·알 수 없는 모델은 허용하지 않는다. 서식 전후에는 같은 문단과 같은 버퍼인지 확인하며 커서를 다른 위치로 옮기지 않는다.

예약 확인 영수증의 생산 값도 기존 소비자 계약인 `YYYY-MM-DD`로 직렬화한다. DB 날짜, 기존 영수증과 승인 판정 함수는 변경하지 않는다. 기존 UTC 자정이 아닌 DB 날짜를 거부하는 계약은 유지되며, 다른 예약 시각 전반의 지원을 확인했다는 뜻은 아니다.

## 실환경 관찰의 범위

별도 격리 편집기에서 원래 고지·첫 문단만 입력해 Enter와 서식 변경을 확인했다. 진단 중 네이버의 변경 요청은 차단했으며 저장·발행·사진 삽입은 하지 않았다. 제목은 차단되고, 본문 선택 표시가 없어도 실제 커서·버퍼가 일치하면 통과했다. 서식 뒤 버퍼 복원과 문단 보존도 실제 화면에서 확인했다.

첫 실제 발행 후보는 테팔 블렌더 소재 1건이다. 중복 확인에서는 해당 블로그 전체 공개 목록 36건과 예약 목록 3건의 실제 문서·상품 링크를 읽었고 일치 글은 없었다. 과거 결과 불명 기록은 삭제하거나 성공/실패로 덮어쓰지 않았다. 이 조회는 당시의 목록 상태이며 발행 직전에도 다시 확인한다.

## 보존 기준

이번 작업 시작 시 원고 80개, 사진 3,958개(3,400,961,774바이트), 생성·참조·체크포인트 기록 569개를 별도 해시로 기록했다. 이전 릴리스 후 사용자 작업으로 늘어난 파일을 과거 상태로 되돌리지 않는다. 기존 승인 정본 15개 파일과 최종 원고·이미지 검사는 유지한다.

보존 검사 중 곶감 소재 한 건에서 별도로 진행 중이던 이미지 작업의 배정 변경이 발견됐다. 기준을 기록하기 전부터 해당 이미지 작업은 실행 중이었다. 기준과 실패 기록을 지우거나 곶감 소재를 이전 상태로 되돌리지 않는다. 이번 발행 대상인 테팔은 이 변경에 포함되지 않는다.
