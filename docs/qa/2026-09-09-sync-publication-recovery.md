# 쇼핑 동기화와 발행 작업 상태 복구 (1.3.48)

## 확인된 사실

- `bulk-seasonal`의 발행 중 오류는 해당 서버 DB의 PUBLISHING 건수 검사에서 반환한다. MCP 큐의 runningJob은 백그라운드 발행 프로세스를 나타내지 않는다.
- 이 작업 호스트의 로컬 앱은 MCP_ACTIVATION_REQUIRED를 반환했다. 원격 MCP 결과와 이 호스트의 로컬 DB를 같은 실행 환경으로 간주하면 안 된다.
- 연결된 원격 PC의 여행 예약 작업은 ECONNRESET 이후 결과 불명으로 남았고, 후속 항목은 중단됐다.
- 원격 상태가 변경된 후 쇼핑 동기화는 발행 중 차단을 넘었으나 `Unexpected token '<'`로 실패했다. 동기화 스크립트가 상품 수집 전에 블로그 게시판 응답을 JSON.parse하고 있었다.

## 수정

- 발행 시도에 실제 자식 PID를 기록한다. 동기화 전 PID 종료가 ESRCH로 확인된 건만 CAS 갱신으로 OUTCOME_UNKNOWN으로 전환한다. 살아 있는 PID, EPERM, 손상된 기록, PID 없는 레거시 기록은 복구하지 않는다. 부모 프로세스 종료만으로 자식 종료를 추정하지 않는다.
- MCP 상태에 backgroundWork의 publishing/drafting/busy를 추가한다. 조회 실패는 0이 아니라 확인 불가로 표시한다.
- 업데이트 준비 상태에 초안 작성도 반영한다.
- 게시판 조회 실패는 상품 동기화를 중단하지 않는다. 확인되지 않은 게시판 번호를 대신 넣지 않으며 기존 상품의 게시판 값은 유지한다.
