# 워크플로 보강 및 품질 기준 정리

2026-09-20. 이전 구조 분석의 발견 사항을 현재 작업본에서 재확인하고 수정했다. 기존 미커밋 변경은 보존했다. 배포·설치본 변경·유료 생성·네이버 실제 발행은 이 작업의 검증에 포함하지 않는다.

## 모델 정책

작성, 수정, JSON 구조화, 주제 후보·선정·편집, 리뷰·문체 분석, 사진 판정과 썸네일 QC는 중앙 `gpt-5.5` 정책을 사용한다. 구형 환경변수의 `gpt-4o-mini` 등으로 조용히 되돌아가지 않는다. 명시적으로 다른 모델을 요청하면 호출 전에 거부한다.

- OpenAI 요청은 `max_completion_tokens`를 사용하고 sampling override를 보내지 않는다.
- 1024토큰 이하의 짧은 분류·제목 요청은 reasoning `none`, 긴 출력은 `low` 및 추론 여유분을 사용한다. Codex는 기본 `medium`이다.
- 모델을 증명할 수 없는 자동 브라우저 **원고 작성**은 고정 Codex 경로로 실행한다. 사람이 직접 작성하거나 외부 ChatGPT에서 제출한 원고의 모델까지 보장하지는 않는다.
- 이미지 **생성**은 `gpt-image-2` 등 이미지용 엔진을 유지한다. 사진 이해·판정과 이미지 생성은 다르다.
- 실제 계정의 모델 접근 권한·응답 품질은 mock 테스트로 입증하지 않는다.

호출 규격과 근거: [text-model-policy.md](text-model-policy.md).

## 과도하거나 충돌했던 기준

| 기존 문제 | 수정 | 유지한 방어 |
|---|---|---|
| 긴 주제명을 본문에서 한 번 언급하면 기계적 문장으로 차단 | 주제명 단순 포함 검사 제거 | 실제 반복 소제목·도입문 검사 |
| 일반 연결어·‘본 포스팅에서는’를 내부 지침 유출로 취급 | 독자용 문체와 실제 생성 지침 유출을 구분 | 입력 키워드·리서치 시그널 등 내부 작성 지침 차단 |
| ‘직접’, ‘써보’, scene 표지만으로 체험성 가점 | 출처가 연결된 비교·조건·선택 분석에 가점 | 출처 없는 숫자·조건 P0 차단 |
| 사용법 두 문장·여행 설명 종류별 문장 수가 단독 필수 탈락 조건 | 구체성 부족은 권고·감점으로 전환 | 상품/방문지 근거, 근거-판단 연결, 안전, 전체 점수 유지 |
| FAQ 정확히 3쌍, 비교 블록 강제 | 확인된 질문·답이 있을 때 최대3쌍, 없으면 생략; 비교도 근거 있을 때만 | Q/A 구조·중복 방지·근거 없는 답 생성 금지 |
| 섹션 문장 수에 ‘답 두 문장’을 추가 요구 | 첫 답 문장도 권장 문장 수에 포함 | 전체 섹션·본문 계약 |
| 전체 소개 제목에 ‘용량’이 있으면 정상 제품 사진까지 배제 | 명시적 전체 소개의 정체 규격과 기능 시연을 구분 | 비교·성능·효과·안전·실측 슬롯은 엄격한 근거 이미지 요구 |
| 썸네일 검사 생략/오류를 pass=true로 반환 | checked=false/pass=false, 재생성 반복 중단 후 원본/로컬 대체 경로 | 최종 상품 픽셀 검사 및 실제 파일 검사 |
| 주제 원고 불합격이어도 이미지 생성·APPROVED 저장 | 본문 통과 후 이미지 작업, 본문·이미지 모두 준비된 경우만 APPROVED | PREPARED는 ‘검토 가능한 초안 저장’이며 발행 허가와 별개 |

일괄적으로 문턱을 낮추지는 않았다. 브랜드 총점70, 주제 자동 발행90, 썸네일 QC95, 본문·섹션·이미지 계약은 유지했다. 이 숫자는 휴리스틱이며 사실 정확도나 검색 노출의 객관적 보증이 아니다. 실사용 결과 없이 새 최적값을 주장하지 않는다.

## 연결 오류 및 운영 방어

- 주제 즉시 발행에 명시적인 `--publish-mode=now` 전달.
- 준비·API·실행 스크립트에 동일한 캠페인 출처 URL 전달.
- 일괄 주제 발행은 통과한 ID 목록을 고정하고 실행 직전에 다시 검사. 개수만 넘겨 다른 대상을 다시 뽑지 않는다.
- 실제 hero 파일 존재·크기 검사. 누락 파일을 제외한 후에도 hero 조건을 다시 검사.
- 이전 최신 글 URL을 이번 제출 결과로 대체하지 않는다. 프로세스 exit0만으로 발행 성공을 만들지 않는다.
- 최종 제출 전에 미확정 상태를 기록한다. 확인되지 않은 제출 결과는 `OUTCOME_UNKNOWN`으로 보존해 일괄 재시도 대상으로 삼지 않는다. 예약 성공은 공통 네이버 응답 검사기를 사용하며 HTTP200만으로 성공을 인정하지 않는다.
- 일반 수정·재준비로 미확정 표시를 지우지 못하도록 차단하고, 준비 시작도 조건부 선점한다. 미확정 작업은 네이버의 실제 게시/예약 결과 확인 및 수동 복구가 필요하다. 단순 재준비를 중복 발행 방지의 대안으로 안내하지 않는다.
- 리뷰 발행 오류는 비정상 종료 코드로 전달한다.
- 여행 이미지 생성에 실제 현재 소제목·본문 요약·이웃 소제목을 전달한다. 이름만 선언돼 사용되지 않던 문맥을 연결했다.
- 원격 heartbeat의 임대 회수/401/403/취소 시 로컬 중단 요청 및 후속 호출 차단.
- 실행 중 원격 작업과 미전송 결과 outbox를 업데이트 idle 판정에 포함. 업데이트 대기 중에도 완료 결과 재전송 가능.
- 업데이트 manifest와 release 포인터를 단일 R2 객체로 게시. 파일 업로드 후 포인터를 전환하며 구형 포인터도 읽을 수 있다. 동시 관리자 배포의 전역 직렬화까지 보장하는 변경은 아니다.
- 레거시 cron은 원자적 claim 사용, 성공 상태를 외부 제출 결과 없이 합성하지 않음, 불확실한 제출을 자동 재큐하지 않음. 구형 payload가 준비 계약을 만족하지 못하면 명시적 실패로 남긴다.

## 검증 구분

새 회귀 검사는 실제 모델/브라우저 대신 mock, 순수 함수, 격리된 실행 함수를 사용한다. 생산 DB·세션을 사용한 실제 게시 테스트는 하지 않는다.

```powershell
npm run test:editorial-calibration
npm run test:text-model-policy
npm run test:topic-publish
npm run test:operational-safety
npm run test:mcp-delivery
npm run test:writing-harness
npm run test:shopping-workflow
npm run test:thumbnail-gen
npm run test:product-section-image-review
npm run test:osaka-audit
npm run test:quality-repair
npm run test:brand-post-package
npm run test:section-images
npm run test:post-spec
npm run typecheck
npm run site:typecheck
npm run build
npm run site:build
```

`test:osaka-audit`의 기존 정상 fixture는 가격·기간만 공급하면서 출처 통과를 기대했다. 실제 검증 계약에 맞는 방문지·일차별 일정 fixture로 보완했으며 출처 없는 경우의 차단은 별도 유지한다. 이전 `test:writing-harness` 격리 오류는 현재 작업본에서 재현되지 않았고 통과했다.

배포 완료·설치 적용·실제 모델 생성 성공·네이버 발행 성공은 별도의 관측이 필요하다. 이번 변경과 오프라인 통과만으로 이를 주장하지 않는다.

현재 설치 폴더의 package 버전은 1.3.60으로 다시 확인됐지만, 새 `scripts/lib/text-model-policy.ts` 파일은 설치 폴더에 없다. 이번 작업본의 보강분은 아직 설치본에 반영되지 않았다. 이전 구조 분석에서 관측한 1.3.58은 과거 시점의 값이다.
