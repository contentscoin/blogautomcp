# /plan 워크플로우

이 워크플로우는 **Atlas** 에이전트를 호출하여 코드 작성 전에 종합적인 구현 계획을 생성합니다.

## 사용 시점

- 새로운 기능 시작 시
- 중요한 아키텍처 변경 시
- 복잡한 리팩토링 작업 시
- 여러 파일/컴포넌트가 영향받을 때
- 요구사항이 불명확하거나 모호할 때

## 워크플로우 단계

1. **요구사항 분석** - 요청을 명확한 용어로 재정리
2. **단계별 분해** - 구체적이고 실행 가능한 단계로 분해
3. **의존성 파악** - 컴포넌트 간 의존성 식별
4. **위험 평가** - 잠재적 문제 및 차단 요소 평가
5. **복잡도 추정** (높음/중간/낮음)
6. **계획 제시** - 사용자 명시적 확인 대기

## 명령어

```
/plan [기능 설명]
```

## 예시

```
/plan 실시간 알림 기능 추가
```

**Atlas 응답:**
```markdown
# 구현 계획: 실시간 알림 기능

## 요구사항 재정리
- 사용자에게 이벤트 발생 시 알림 전송
- 인앱, 이메일, 웹훅 등 다중 채널 지원
- 신뢰성 있는 알림 전달 보장

## 구현 단계

### 1단계: 데이터베이스 스키마
- notifications 테이블 추가
- user_notification_preferences 테이블 추가

### 2단계: 알림 서비스
- lib/notifications.ts 생성
- 큐 시스템 구현 (Redis/BullMQ)

### 3단계: 프론트엔드 컴포넌트
- NotificationBell 컴포넌트 생성
- real-time 구독 구현

## 위험
- HIGH: 이메일 전달성 (SPF/DKIM 필요)
- MEDIUM: 대량 사용자 성능

## 예상 복잡도: 중간

**확인 대기 중**: 이 계획으로 진행할까요? (yes/no/modify)
```

## 관련 에이전트

- **Atlas** - 계획 수립 및 아키텍처 설계
- **Prometheus** - 시스템 설계 심화 분석
